# 安装包构建性能审计（2026-09-29）

## 已确认的根因与修复

开发前端的 `emptyOutDir: false` 用于保留旧 WebView 会话依赖的 chunk；原桌面发布也直接收集这个开发目录，导致每次构建都把历史文件加入安装包。实测开发目录有 **3,323 个文件 / 494.64 MiB**。新的桌面构建使用独立暂存目录，成功后原子替换 `desktop/.cache/frontend-dist`，electron-builder 只收集该目录。相同源码的干净产物为 **537 个文件 / 43.84 MiB**，减少 **450.79 MiB / 91.1%** 的前端输入，开发目录不受影响。Vite 自报编译时间为 **3.63 秒**。

FFmpeg 原流程每次都重新解压 ZIP，再复制运行时。现在把已解压运行时放在 `desktop/.cache/ffmpeg/runtime`，复用前验证固定 ZIP 的 SHA-256、运行文件及许可证的内容哈希、版本与 `h264_mf` 编码器。失效时重新提取。首次执行进程耗时约 **2.68 秒**，缓存命中约 **1.47 秒**。

后台宿主原流程每次执行 `dotnet publish`。现在按源码、外部嵌入图片/图标、SDK、NuGet 还原状态和上层 MSBuild 配置缓存，并校验所有输出文件（包括语言子目录）的内容。输入或输出变化都会重新构建。首次执行 **4.93 秒**，缓存命中 **1.05 秒**。设置 `DESKTOP_FORCE_ADMIN_REBUILD=true` 可强制重建；Unity 原有的 `-ForceUnityBuild` 仍可使用。

## 持续诊断

`npm --prefix desktop run dist` 和双击入口现在统一进入 `生成安装包.ps1`，按依赖安装、前端、Unity、后台宿主、资源准备、生成程序目录、首次运行 MySQL 验证、NSIS 压缩记录耗时。成功或失败都会保存独立发布目录内的 `build-timings.json`，并镜像到 `desktop/.cache/build-timings.json`。npm 入口现在接受发布脚本选项，例如 `npm --prefix desktop run dist -- -StarterTemplate`，不再单独绕过首次运行验证。

后端依赖为 **14,055 文件 / 97 MiB**，原始独立 tar 测量 **6.17 秒**。现已增加归档缓存，按锁文件、Node ABI 和依赖文件的路径、大小、mtime/ctime 等状态失效，并对缓存 tar 验证 SHA-256。归档前后状态变化时拒绝发布，保留旧缓存。本机首次建立缓存及双重检查 **11.00 秒**，热缓存检查并复制 **2.48 秒**。首次冷构建有所增加，重复构建省去逐文件重新归档。

依赖安装入口不再仅凭 node_modules 目录存在就复用；成功安装后记录 package.json、package-lock.json、已安装隐藏锁文件和 Node 运行时指纹，变化则重新安装。首次升级到此逻辑没有可信安装记录时会执行一次安装；失败安装不会留下成功记录。后续无变化直接复用，`-RefreshDependencies` 仍可强制安装。

未改动的必要工作包括现场配置快照、MySQL 运行时验证和安装包压缩。Unity 已有源码内容缓存，检查到的 Assets 仅 **97 文件 / 4 MiB**，本轮没有强制重建 Unity。

## 验证边界

完整 StarterTemplate 发布链路随后已通过，记录见 `安装包/release-20260929-063838-477/build-timings.json`：总耗时 **328.06 秒**，首次独立 MySQL 验证 **85.81 秒**，NSIS阶段 **183.54 秒**。这证明余下最大瓶颈是压缩。

进一步核查 electron-builder 实现发现 `compression=normal` 的 ZIP 实际默认 `-mx=7`。对同一个已验证的 win-unpacked（1,636文件，1,455,636,674字节），用相同7za和Deflate参数分别实测：

| ZIP级别 | 耗时 | 压缩字节数 |
| --- | ---: | ---: |
| 7（旧默认） | 160.175秒 | 546,400,713 |
| 1（新默认） | 12.573秒 | 579,186,207 |
| 3 | 12.868秒 | 579,186,207 |

因此发行脚本默认设置 `ELECTRON_BUILDER_COMPRESSION_LEVEL=1`：ZIP阶段少147.6秒、快12.7倍，压缩文件约增6.0%（31.27MiB）。用户已设置的环境值优先，包括0；成功或失败都会恢复调用前环境。发布清单记录实际级别。已用实际脚本压缩块验证默认/3/0与成功/失败的6种恢复组合。审计结果保存在 `output/compression-audit-clean-20260929-0651`。上述加速仅指ZIP阶段，新默认的最终NSIS时间应以重压报告为准。
