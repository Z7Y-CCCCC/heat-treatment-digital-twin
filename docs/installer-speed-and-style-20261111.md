# Windows 安装包：自动复用与界面更新

双击根目录 `生成安装包.cmd`，或执行 `npm --prefix desktop run dist`，均走同一个发布流程。

第一次构建以及应用源码、版本、依赖变化后执行完整构建。之后应用内容相同时自动复用已完成全部运行验证的程序目录，只生成新版安装界面和安装程序。原有手动入口 `node tools/installer-repack.cjs <已完成发布目录>` 也保留。

复用基于完整源码内容清单，包含未提交修改、中文文件名、新增与删除文件；不会因为工作区有本地修改就每次重新构建。仅安装插画、安装窗口、文档和构建工具的变化允许复用。源清单在完整构建生成程序前记录，交付前再次核对。快速重包前后校验程序目录全部文件，并核验可选采集插件、空系统策略、成功测试记录和版本。缺失、损坏或未完成的包不会当作已验证缓存。

版权说明属于资源准备阶段的生成文件，需先准备 FFmpeg/MySQL 许可证资料，再由原流程生成。源码清单不把该生成结果当作构建输入；完整构建和快速复用均单独核对它与已验证程序内的版权说明，仅允许 Git 的 CRLF/LF 换行转换。删减、变更或缺失许可证文字仍使验证失败。安装资源自身继续逐字节核验。

`release-manifest.json` 区分完整构建与 `installer-ui-only`；后者标记复用了哪次完整运行验证。`build-timings.json` 保留分阶段耗时。只有完整构建和运行验证全部成功才更新 `desktop/.cache/last-verified-release.json`。

未交付的候选目录在运行测试或交付收尾失败后，可指定 `-ResumeCandidate -ReleaseDirectory <候选目录> -BuildOutputRoot <原构建输出根目录>` 续建。续建必须先匹配完整的编译成功记录、源码内容和原始程序基线，保留原来的失败记录，重新执行全部运行验证；不会复用未通过的测试，也不会覆盖已交付安装包。

需要重新验证运行环境、更新 SDK/运行库或强制执行完整流程时：

```powershell
npm --prefix desktop run dist -- -FullBuild
```

完整构建将项目迁移验证与运行环境验证重叠执行，各用独立数据目录。采集服务与大屏首次启动使用相同的生产端口搜索方式，仍串行执行这两项，避免端口探测竞争。未减少首次安装、重启持久化、迁移回滚、停库和安装资源完整性检查。各测试日志和结果写入发布暂存目录 `runtime-checks`。

安装包校验值改用 .NET 流式 SHA-256，不再依赖 PowerShell 自动加载 `Get-FileHash` 模块，修复构建完毕却在生成交付信息时失败的问题。NSIS 预览及界面资源生成使用 electron-builder 自己解析的工具目录，兼容不同缓存布局。

界面采用深蓝工厂插画、白色内容区和蓝色主要按钮，调整字体、间距、路径输入区与文案。安装、需要重启、失败、取消仍使用真实原生 NSIS 页面；不会自动重启。升级与卸载保留已有用户数据，许可证及采集插件分离策略保持原样。

本机实测：此前默认流程记录总耗时 410.646 秒；新的默认入口在应用内容不变时耗时 50.971 秒（整个入口的实际运行时间），其中重包内部记录 42.210 秒。约减少 88%。这不是修改业务代码后的完整构建耗时，也不包含首次下载依赖的时间。完整运行验证已通过，复用前后均核验了 1,686 个程序文件。新版安装包内的压缩内容测试通过。

界面验证命令（只运行不会安装软件的预览）：

```powershell
npm --prefix desktop run preview:installer
node --test desktop/scripts/installer-ui-test.cjs tools/installer-repack.test.cjs tools/release-source-snapshot.test.cjs
```
