# 自选产线设备模拟联动

入口：模型库 → 动作动画 → 设备联动。

1. 选择产线。设备列表来自当前工厂的设备实例，不从模型库创建临时设备冒充现场设备；同型号多台设备按设备 ID 分开模拟。没有设备时，先在设备管理中分配产线和模型。
2. 勾选参与设备，可搜索、分页、全选或清空；使用 ↑↓ 调整模拟顺序。可选一台该产线的料车作为配送设备。
3. 选择“按模拟顺序排列”或“沿用现场设备位置”。前者只调整本次预览，后者复用车间、产线和设备坐标、朝向、镜像及缩放。
4. 点击“开始联动”，或者先“预览选中设备”。可关闭工艺动作，仅演示送料和取料。

有料车时，按已选作业设备顺序执行：料车定位 → 开门（有门设备）→ 送料 → 退链 → 关门 → 设备工艺 → 出料开门 → 取料伸链 → 物料回车 → 关门，然后前往下一设备。无料车时只演示各设备动作，不假装发生跨设备搬运。没有动作配置的设备标记为“仅展示”，不伪造其机构运动。

设备工艺复用已实现的动作：清洗机注水/喷淋/排水/吹扫，水冷槽下降/搅拌/升起/沥水，备料台升降/辊道，风冷台风机，以及已有模型中明确配置的部件运动。原超声波清洗机的工艺效果仍可通过选中的实际设备实例预览。新回火炉支持已知门板和滑架节点。

联动工步分页显示；支持暂停、调速、进度定位、复位、自动跟随当前工步、当前设备特写和整线视图。调整参与设备、顺序、排布、模型或产线时停止并清除旧预览；异步模型加载有取消保护。一次选择多台料车、缺少模型文件、缺失已配置门体节点时明确提示，不用替代模型掩盖失败。

这是只在后台页面运行的模拟：物料、链条延伸及路线为示意，未做碰撞检测或避障规划，工步时长不是现场工艺参数。它不修改设备/产线/模型配置，不读写 PLC，不向 Unity 现场场景发布导航或运动命令。关闭预览后临时几何、材质、贴图及 GPU 渲染器被释放。

验证：

```powershell
npm --prefix frontend test
npm --prefix frontend run build
# 指定本机 Playwright 和 Chromium/Edge 路径后执行；默认自建独立数据库及后台。
node tools/line-simulation-ui-test.cjs
```

`line-simulation.test.mjs` 验证产线归属、实例顺序、门/推链/物料/工艺时序、确定性进度定位及无源数据修改。界面验收覆盖六种 CAD 模型共同加载、同型号独立实例、新回火炉、原清洗机、切线清场、现场排布、多料车拒绝及重置，并核对测试数据库的设备和产线保持不变、没有配置或 PLC 写请求。
