# 数据接入与绑定对照复查

日期：2026-11-02。基线：`704ace1`。本次是 Ethan 指定的参考研究和现状复查，**没有把下述设计冒充已实现，没有更新或重启现场，没有验证安装包**。

## 1. 结论

此前把“增加协议入口、连通性测试、单字段预览”当作数据接入主要交付，范围过窄。真正缺口是可复用的数据集、请求参数化、结构转换和对象上下文联动，不是多几张协议图片。

应分清四件事：

1. **连接**：服务地址、协议、认证与连接生命周期。
2. **数据集**：读什么接口、表或主题，传什么参数，结果结构是什么。
3. **字段处理**：结果中的哪一组数据，哪些字段是设备 ID、时间、数值、状态、分类。
4. **绑定与联动**：哪些组件或模型使用该数据集，怎样随当前设备、点击、筛选和时间范围更新。

现有 Unity＋WebView2、设备采集、数据库多数据项与公式、发布迁移应保留，不换引擎，也不把它们误说成没有实现。

## 3. 多种绑定情况的实际差距

| 使用情况 | 当前已经有的能力 | 本次确认的不足 | 应补的工作流 |
|---|---|---|---|
| ERP / MES 认证 | API Key、Bearer、Basic、OAuth2 client credentials；凭据只留后台 | 不支持任意业务登录接口→提取自定义 Token 字段→附加到后续请求的通用配置；不能把标准 OAuth2 说成已覆盖所有登录方式 | 独立认证配置、Token 路径、有效期与受控刷新；连接测试和业务数据测试分开 |
| HTTP 查询 | 固定根地址和相对路径、GET、JSON/XML/CSV、字段检查 | 不能配置业务读取 POST、Query/Body 的上下文参数；固定 JSON 路径不能表达“当前设备那条记录” | 数据集编辑器配置只读请求、参数来源、参数类型与缺值策略 |
| 图表、表格、文本 | 标量读取、原始数组、图表的分类/数值字段配置 | 缺统一的数据集字段模型、预览转换结果和复用；不能把已有数组读取说成完全不能画图 | 选结果根节点→字段重命名/类型/单位/时间→预览标准行；一个数据集供多个组件引用 |
| 点击不同设备显示详情 | 数据库绑定已有 device/line/workshop/part 上下文；现有原生视角和对象事件链 | HTTP 没有等价参数与行匹配映射；容易各设备复制固定路径和组件配置 | 当前对象 ID→外部业务 ID→参数/行过滤；同一弹窗模板跟随对象复用 |
| 下拉框、按钮、时间联动 | 组件事件、部分视角显隐规则已有 | 没有统一的类型化页面参数及数据集依赖关系；不能把教程高级脚本都算作现成可视化规则 | 控件更新上下文→依赖数据集失效重读→相关组件增量更新 |
| 三维属性与批量绑定 | PLC 已能驱动模型部件、显隐、颜色等 | 外部数据集没有贯通到同一套设备/部件属性契约；缺批量核对业务标识的入口 | 属性映射表，支持单项/批量校验，缺失和重复 ID 不静默匹配；沿用 Unity 现有绑定器 |
| MQTT / WebSocket 等 | 有真实协议读取、并发取样合并和短时缓存，不是假按钮 | 当前收到一次数据后就断开，之后按需再取样；不是常驻订阅，不能保证取样间短事件不丢失 | 独立服务中的长连接/主题管理、重连、最新快照、质量和过期时间；浏览器只消费结果 |
| 多源计算 | 最多 12 个数据库数据项、聚合、别名和数学公式 | 不能把数据库的多项公式直接等同于 HTTP/PLC/流数据统一计算；多行公式按下标组合不是按设备或时间关联 | 显式关联键、时间对齐、缺值处理；不同设备数据不得靠数组位置硬拼 |
| 复制与迁移 | 项目包、资产哈希、发布快照和引用映射已有 | 新数据集、参数、属性绑定需要纳入同一迁移契约 | 检查连接依赖→重绑连接→验证字段；不迁移密码，不另造一套项目打包机制 |

数据源类型目录里仍有待接入的驱动。官网列出的完整类型集合和本项目当前实际能力不能混为一谈。

## 4. 已执行的隔离诊断

执行：

```powershell
node tools/data-binding-baseline-audit.cjs
```

该脚本只创建独立 `output/binding-gap-probe-*` 数据目录和自己的回环 HTTP 服务，不读取现场配置、不连接真实 ERP/PLC，也不修改任何运行服务。它记录能力是否存在，而不是把缺陷行为作为将来必须保持的 CI 测试。

基线观测：

- 合成接口返回设备 A=700、B=850；同一固定 HTTP 路径绑定在两个设备上下文中均读到 700。说明 **HTTP 尚无按当前设备选择/传参的配置能力**，不是已经证明现场发生跨设备泄露。
- `{department, quantity}` 数组的两行原样保留，但没有变为 `{label, value}` 序列。现有组件可以另选原始行字段，所以这不是“所有 HTTP 数组都不能显示”；缺的是可复用、明确的数据集整形。
- 两个组件读同一接口响应中的不同字段，首次运行产生两次 GET。已有结果缓存，但缓存按绑定区分，不能代替按完整请求身份合并响应。
- 提供未受支持的 `method: POST` 不会建立 POST 读取，实际仍为 GET。后续增加请求方法必须贯通保存、校验、预览和运行，不能只加下拉框。

对应源码：

- `backend/services/dataSources.js`：`normalizeHttpBinding`、`fetchHttpApiPayload`、`readHttpApiBinding`、`readRuntimeBindings`、`compositeRows`。
- `backend/services/dataSourceTransports.js`：`networkSample` 与 `readTransport`。
- `frontend/src/views/admin/components/DataSourceWorkspace.vue`、`DataSourcePreview.vue`、`DashboardDesigner.vue`。
- `frontend/src/runtime/WidgetRenderer.vue`：原始行和图表序列消费方式。

## 5. 改造顺序与界面

### 第一批：把一个完整场景做通

以井式炉设备详情为验收对象：本机 ERP 测试接口 → 认证 → 可复用数据集 → 按设备 ID 查询/匹配 → 字段映射 → 同一详情面板。设备参数仍来自自带采集；不要用 ERP 数据覆盖 PLC 的实时参数来源，也不要重新加载 Unity 场景。

数据源区域采用横向 **连接 / 数据集 / 绑定 / 运行状态**；各编辑区内部再用 **请求 / 认证 / 参数 / 字段 / 预览** 切换。连接列表、请求配置、返回数据明确分区，固定保存区；不把所有表单和大段说明向下堆。

组件侧只需选择数据集和字段，并映射“当前设备”等参数；不重复填写 Token、整段请求和同一套字段路径。

### 第二批：数据处理、筛选联动与复用

支持记录匹配、字段选择/重命名、类型转换、倍率/偏移、聚合、状态映射以及当前设备/产线/时间参数。先提供可视化、可校验的常用转换；不直接把任意教程 JavaScript 放进 Node 后台执行。高级扩展如需开放，另定隔离、资源限制及生命周期契约。

### 第三批：持续接入与缺失驱动

把流协议从临时取样升级为常驻管理，并逐项验证目录中待接入驱动。所有连接必须分别标明“配置存在、连接成功、收到数据、字段有效、运行绑定生效”，不能一个绿色检查覆盖全部状态。

## 6. 必须跑通的验收

1. 普通 Token 和自定义登录取 Token 两条链路；错误认证不泄露凭据，失效后受控刷新，不无限重试。
2. GET / 明确声明的只读 POST、JSON 嵌套对象/数组、中文字段、空数组、`null`、有效零。
3. 点击 A/B 共用面板，温度/工单分别匹配；无上下文不偷偷退化成读取全表第一条。
4. 快速点 A→B，让 A 后返回：面板必须保持 B，旧请求不得覆盖新对象。切页/切场景也取消旧订阅。
5. 一个接口给多个字段/组件使用，只请求一次并按响应快照分发；权限、工厂、参数、认证版本不同不能错误共用缓存。
6. 断网、恢复、无数据、字段被删分别显示质量，不把错误转换成零或继续冒充最新值。
7. 发布后、重启后，WebView 图表与 Unity 属性绑定均使用正式数据集定义，不依赖编辑器缓存或手工刷新。
8. 导入项目时连接和数据集引用检查完整，业务凭据不随包迁移；原有 PLC 采集不受影响。

以上为完整改造范围，不代表全部能力已交付。第一批的实现、使用入口和尚未完成的边界见[可复用数据集与组件绑定](可复用数据集与组件绑定.md)；安装包和现场系统验收另行进行。
