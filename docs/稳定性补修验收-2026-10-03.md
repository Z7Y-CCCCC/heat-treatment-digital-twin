## 本轮补修

### 后端

- 数据源缓存增加 TTL 清理、256 条/16 MiB 预算和 LRU；配置修改后，旧异步查询不能回填过期配置缓存。
- DataEngine 和 Simulator 在异步读取工厂设置后核对运行代次；旧启动不能在 stop/restart 后恢复，更不能覆盖新工厂身份。
- 指标快照写入单飞；慢数据库不再积累每个采样周期的写入任务。
- 报警只记录有效质量的跳变，先写独立 SQLite 持久队列，再以最多 32 条的批次送入业务库。数据库故障时退避，内存不保存完整采样帧；积压计数不每帧全表扫描。
- 业务库为报警增加唯一 collector_event_id；提交已成功但本地确认失败时，重试不重复入库。可靠报警仍保留，未增加自动删除报警/操作事件的策略。
- 停止过程等待报警和指标写入，关闭持久队列；日志和健康接口明确记录持久化失败。
- 整站备份 v4 包含一致性报警队列快照，并兼容 v1–3；快照先于业务数据库快照，避免确认时间窗口把事件漏在两个快照之外。恢复合并可靠待写事件，保留现场已有观察状态，失败回滚。
- 数据库并发关闭修正就绪状态；并发测试也补齐 finally 释放，解决失败后无活动句柄却退出 0 的假绿。
- MySQL 主连接池排队改为有界，连接获取、语句、整个事务均设置期限。超时只销毁本次独占连接；迟到的连接归还，迟到的事务回调不能继续写入或提交。数据库传输故障/超时取消健康状态，成功查询后恢复；普通 SQL 语法错误不误判数据库离线。
- 整站恢复在任何业务修改前持久发布意图，独立保存并校验源 ZIP、原业务库、报警队列证据。主库提交状态未知、报警队列提交失败、意图退休失败时，保留 staging 与证据并报告待决恢复；冷启动停止采集、维护和业务接口，健康接口不能报 displayReady。只有明确完成或确认回滚成功后才退休意图；证据清理失败单独报告。
- 私有 MySQL host 在任何 schema 模块加载前绑定所属 root/data 与内部备份、恢复、导入、缓存路径；独立采集服务和随包桌面后端同样绑定内部可写目录，不继承无归属的业务连接与写路径。父环境不改写，开发模式仍支持原环境配置；应用已保存的外部备份镜像仍按原优先逻辑生效。
