# 趋势显示窗口与原始记录

## 旧限制的问题

旧实现把图表的内存点数和时间窗口绑在一起：输入最多 10 分钟、内存最多 600 点，页面关闭即失去这部分曲线。全厂指标快照不是每个点位的原始采样，不能用它恢复之前没有落库的炉温等曲线。

## 现在的边界

- 实时窗口按分钟填写：`30` 为半小时、`60` 为一小时，支持更长时段，不再压回 10 分钟。
- “画面绘制点数”只限制浏览器绘图预算。超出时保留时段首尾、极值和断线空值，并从后台重新补读；不删除任何数据库原始记录。
- 独立采集器将**已经配置且实际采集到的点位**按采样时间记录进 `point_samples`：工厂、设备、点位、采样时间、原始值、质量和模拟/PLC 来源分别保存。缓存重复推送不当作新采样；模拟值不冒充 PLC 值。
- 点位默认只记录**近期 24 小时滚动趋势**，不是默认永久保存。长期历史按点位选择；全厂指标默认保留 90 天，可独立关闭、改期限或永久保留。窗口缩短、轮播、关闭大屏或采集运行中心不修改保存策略；实际记录仍要求采集服务运行。
- 数据库暂时不可用时，原始采样先进入本机持久队列，随后分批重试；入库确认丢失不会产生重复记录。内存只保留有界批次，积压在磁盘而不是无限增长的内存中。
- 业务库每批事务成功提交后，可靠队列在**单个事务内批量确认**该批采样，避免高频多点采集逐条删除时反复同步磁盘。队列继续使用 WAL 与 `synchronous=FULL`，不提前确认、不关闭同步；删除中途失败整批回滚，业务提交后确认丢失则按采样唯一键幂等重放。
- 已入库记录随完整数据库/现场备份保存，待入库队列随既有可靠事件快照备份。工程配置包不等于历史数据备份。
- 磁盘写入失败会明确报告，不能声称未成功写盘的采样已经安全保存。“永久保留”不等于无限磁盘或替代异机备份，仍需监测空间并安排完整备份。

## 设置入口与默认策略

后台 **数据中心 → 点位映射 → 趋势与历史记录**，展开设置；自动沿用当前大屏的工厂，无需在面板中另选工厂。没有浏览器工厂偏好时由后端解析当前工厂，保存固定到读取确认的工厂，不能把空偏好误报为“请先选择工厂”。设备可筛选为全部或单台。

| 设置 | 选项 / 默认值 |
|---|---|
| 近期趋势记录 | 默认开启，保留 24 小时；可关闭，或设置 1～720 小时 |
| 当前点位保存方式 | 默认“仅近期趋势”；可“不记录此点位”、“长期按天保留”或“长期永久保留” |
| 点位长期期限 | 1～36500 天；实际期限取近期窗口与长期期限中较长的一项 |
| 全厂指标历史 | 默认按 90 天保留；可关闭、设置 1～36500 天或永久保留 |

工厂策略和点位策略分别保存。关闭工厂近期趋势后，已经单独开启长期记录的点位仍继续记录；“不记录此点位”则明确关闭该点位的两种记录。关闭历史记录不影响实时值和当前页面曲线；重开页面只能恢复确实保存且未到期的数据，不能补造未记录或停机期间的数据。告警与操作事件不受这套策略影响。

策略存储于当前工厂的 `history_policy_v1` 与点位的 `history_mode/history_days`。采样进入可靠队列时确定 `retention_until`，入库重试保持原期限，不按入库成功时间延长。策略修改只影响后续采样，**不会立即删除或改写已有历史**；旧版无到期时间的数据继续保留，有限期限的旧记录仍按原到期时间到期。后台按有界批次清理到期的点位/指标记录，不清理事件、项目发布或现场配置。

`GET /api/datapoints/history-policy?device_id=设备ID` 读取当前工厂策略和已保存点位；`PUT /api/datapoints/history-policy` 保存工厂策略；`PUT /api/datapoints/history-policy/points/点位ID` 保存单点策略。沿用既有后台登录、点位编辑权限和 CSRF 校验，不允许跨工厂点位写入。配置工程包可携带用户显式设置的策略，但不含历史记录；出厂资源仍保持空业务数据。

## 只读查询

`GET /api/datapoints/history`：按当前工厂、设备和点位查询指定时段的绘图样本；保留原始时间、极值、断线空值。响应标明 `drawingOnly: true`。

`GET /api/datapoints/history/records`：原始记录按时间与记录键进行游标分页，包含模拟/真实来源与质量，不是绘图降采样结果。响应标明 `drawingOnly: false`。

共同参数：`device_id`、`point_id`、毫秒时间 `from`/`to`、`limit`（20～5000，默认 2000）。工厂通过既有 `X-Factory-Id` 上下文指定，必须通过原有访问校验；绘图可另传 `source_mode`，原始分页接续参数为返回的 `after_time` 与 `after_key`。禁止跨工厂或跨设备读取点位。

## 更新与验收

这是源码功能更新，不是安装包发布，也不修改本机现场配置或出厂模板基线。已安装的旧服务不会自动获得原始记录功能；需要更新相应程序后生效。之前只在页面缓存、没有入库的记录不能补造。

隔离测试：

```powershell
node backend/scripts/point-history-test.cjs
node backend/scripts/point-history-ack-test.cjs
node backend/scripts/history-policy-test.cjs
node backend/scripts/history-retention-test.cjs
node backend/scripts/collector-process-integration-test.cjs
node backend/scripts/project-bundle-test.cjs
npm --prefix frontend test
node tools/point-history-ui-test.cjs
```

浏览器工具使用 Playwright，可通过 `PLAYWRIGHT_MODULE` 与 `BROWSER_EXECUTABLE` 指定依赖。上述测试只使用隔离数据库，不触碰现场服务或现场数据。

策略保存后沿用采集器配置热加载，不要求重启 Windows 服务；热加载同时刷新工厂和点位保留策略。产线设备和直接挂在车间下的设备都支持，设备显式产线归属优先，不能通过车间提示串到其他工厂。工程包回归覆盖策略反复导出/导入和非法策略拒绝，工程包不携带原始采样。

浏览器验收夹具在加载模块前固定 API 到自己的隔离服务器，并拒绝任何跨源请求；不能因开发端口或本机环境设置误连现场采集服务。
