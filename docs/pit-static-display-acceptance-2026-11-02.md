# 井式炉静态展示与数据接入

本轮只做静态模型、页面导航和参数展示，不配置动作动画、不下发 PLC 指令。

## 已发布内容

- 保留 CAD 对应的 17 个对象、设备标高及 10 处基坑，不更改设备/PLC/点位/模型配置。
- 从天津当前发布稿复用 WebView 控件的样式与组件类型，重新绑定井式炉设备；不复制天津点位、数据值和设备跳转。
- 工厂/车间/产线：生产订单、监控台账、9 台炉体温度与详情入口。移除底部两排截断的设备按钮，底部留给 WebView；17 个对象通过既有层级选择器或模型点击进入。
- 9 台炉体详情：实际温度、设定温度、循环风机转速和状态、炉盖状态、设备运行、报警，共 63 项参数展示。数据来自既有内置采集数据帧，不从 ERP/VMS 获取。
- 8 项辅助设施详情：模型长宽高、编号、型号和位置；不显示虚构的过程参数。
- 按 Ethan 要求，运行页面不堆放“模拟”“非现场”、接入说明和重复提示。数据来源边界记录在配置元数据和本说明中，不冒充现场接入验收。
- Unity 与后台 Three.js 预览中的厂房墙体、屋顶改为 10% 不透明度，不写深度、不投实心阴影；设备保留原材质。地面及基坑不透明，原始模型资产不变。
- 建筑不参与设备拾取，设备仍使用精确模型网格拾取，而不是以包围盒替代；厂房每种材质仅创建一个展示副本，销毁时释放。
- 工厂/车间/产线总览悬停设备时显示 2px 淡青色网格轮廓；移开、隐藏、切换视角/工厂或被 UI 阻挡时清除。仅绘制当前悬停设备，复用现有部件描边着色器和拾取缓存，不替换设备材质，不增加相机、渲染纹理或后处理。

## 数据来源边界

井式炉设备原本均未启用 PLC，尚无现场点表。本轮保留原有 `simulation` 运行模式，用系统内置模拟采集链路展示设备参数，没有编造或启用任何 PLC 地址。

ERP 与 VMS 使用两份受控样例导出，经过正式外部数据源连接器读取，不是写死在组件里的数值：

| 数据源 | 本轮实现 |
| --- | --- |
| `pit_demo_erp` | JSON 导出：9 条订单、各设备关联批次和物料 |
| `pit_demo_vms` | JSON 导出：4 条摄像头台账、设备关联通道；没有真实视频流 |

两者均为工厂隔离、只读、5 秒刷新；数据文件保存在应用私有目录，连接和文件可随既有整站备份保存。没有增加常驻模拟服务、额外 Electron 或新渲染引擎。替换正式数据时使用后台“外部数据源”配置对应连接，再重新绑定字段。

## 自动验收

```powershell
# 隔离后端/API 回归（不连接现场数据库）
node tools/pit-static-display-test.cjs

# 使用本机已有 Playwright 依赖的隔离 WebView 页面回归
$env:PLAYWRIGHT_MODULE = 'PLAYWRIGHT_MODULE_PATH'
$env:BROWSER_EXECUTABLE = 'CHROMIUM_EXECUTABLE_PATH'
node tools/pit-static-display-test.cjs --ui

# 原生 Unity 隔离场景：正式 GLB、地面、材质、17 设备网格点击及正/斜视图渲染
node tools/native-hall-visibility-checks.cjs
# 分目录构建现有场景，不覆盖正在使用的客户端
node tools/native-hall-visibility-checks.cjs --build

# 已授权管理会话提供 ADMIN_API_TOKEN，不在命令或仓库中记录其值
$env:PIT_CAD_ORIGIN = 'http://127.0.0.1:3001'
node tools/pit-static-display.cjs
node tools/pit-static-live-verify.cjs
```

验收覆盖：

1. 仅修改目标工厂设计稿和两个外部样例连接；天津草稿修订、发布稿哈希不变。
2. 重复应用不重复导入文件或增加设备/控件，设备与地面逐字段不变。
3. 真实页面通过既有设备选择器切换 17 个对象并发出正确原生导航请求，9 台炉体读各自的采集值和批次，辅助设施不串用炉体值。
4. 页面无“模拟/非现场/示意/估算”等说明性文案；主要控件保持同屏，未选中的详情组件不渲染。
5. 隔离环境移除 ERP 导出后，外部值质量转坏，不替换成 0；VMS 和内置采集继续运行。
6. 本机 Unity 逐个切换 17 个设备实体视角，检查可见性、内部采集帧与静态变换，最终回到产线总览。此过程使用项目 MCP、原生接口及 WebSocket，不使用 Computer Use。
7. 1366×768、1600×900 下主要参数完整显示，设备详情标题不与固定层级导航重叠，底部不再渲染设备快捷按钮。
8. Unity 隔离场景加载正式厂房及 17 个模型；保留 10 处基坑，逐个调用实际鼠标网格拾取路径；核查建筑透明着色器、阴影关闭、材质共享/释放和设备原材质不变。原生正/斜视图导出到 `output/hall-visibility-*`，不是桌面截图。

本轮回归结果：前端 478 项通过；隔离 WebView 验收通过、浏览器异常为 0；原生设备悬停 27 项通过（含原材质不变、静止光标持续描边、移开/切换清除与材质复用）。厂房回归另外核查实际渲染中的轮廓像素及 17 台模型点击。现有场景的 Windows 客户端分目录构建成功，未运行场景/配置重建。构建文件不进仓库。

后端全量首轮 64/66：`site-recovery-intent-test` 的 Windows 文件替换错误码与 `database-retention-test` 的启动清理计数各出现一次失败；两项单独复测均通过，未将其掩盖为全量一次通过，也未混入无关后端修改。桌面日志、进程及资源检查通过。

工具在 `output/pit-static-display-*` 保存应用前后私有快照和测试截图，在 `output/pit-static-live-*` 保存原生核验结果。快照可能含现场连接信息，不上传。回滚仅恢复目标场景先前设计稿并重新发布，不整库覆盖；两个样例连接与原始文件可以保留或在确认无组件引用后从后台删除。
