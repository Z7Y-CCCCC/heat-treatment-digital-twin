# 通用低代码拆解：续作与验收

日期：2026-09-12（Asia/Hong_Kong）。续接任务 `01a08d5e-eddf-7530-94b4-a4d087c19e2d` 中尚未完成的设备拆解改造。此前的软件排查与 PLC 加测结果保留，本轮不重复宣称已验证真实现场硬件。

对标：[MF-TurbineMonitor](https://fengtianxi001.github.io/MF-TurbineMonitor/)。本轮实现的是同类的外壳先退场、总成按方向分阶段展开、联动镜头、空间标签、高亮选择、参数上下文和反向组装，不是将涡轮模型或布局复制到热处理设备。

## 工程师入口

1. 打开后台的“模型库”，选择已有模型或导入模型。
2. 进入“拆解检查”。已有设备样板可直接预览；也可应用可编辑预设、从真实装配组追加部件，或手工新增部件。
3. “部件与运动”配置中文名称、稳定 ID、分组、多节点目标、位移、XYZ 转角、额外延迟、时长、标签偏移、说明、特写镜头和 PLC 点位关联。
4. “外壳与时序”选择外壳节点、裁切/渐隐/定时隐藏、坐标系、外壳退场时长、缓动与部件间隔。“镜头与标签”可记录当前预览镜头。
5. 用“演示拆解”“反向组装”、暂停/继续和进度条验收。点标签或模型部件可特写、单独查看。草稿编辑不会改变已有 PLC 动作的原节点变换。
6. 点击“保存拆解配置”。保存后重新打开仍保留完整字段；普通编辑不需要写 JSON。JSON 导入/导出是高级交换入口，并有替换确认。
7. 同型号设备继承模型配置；设备已有独立覆盖配置时，仍按其覆盖设置工作。需要临时验收时，在“配置与运行端”选择使用该模型的设备，推送未保存草稿。没有连接的 Unity 时会明确报错，不假报发送成功。

草稿预览只改变目标设备的内存展示，不写业务库。运行端重新加载/重置后丢弃草稿。保存模型配置后，后台会通过 WebSocket 通知 Unity 自动重新加载；如果运行端当时不在线，则下次启动时读取数据库中的最新配置。

## 补齐与修复

- 后端与浏览器使用同一份 v2 规范化实现；不再丢失多节点、首个外壳节点、时序、旋转、标签、镜头和禁用状态。显式空部件列表不会被旧 PLC 绑定重新填回。
- 保存/预览校验重复 ID、未选节点、缺失/歧义节点、跨部件相同或父子目标、外壳与部件的父子重叠、数量限制。歧义节点名称需要改用完整路径；外壳必须选择实际外壳网格/节点，不能选择包含内部总成的父节点。
- 修复拆解中内部组件被误隐藏的问题：旧版或绕过校验的宽泛外壳配置在运行端会安全跳过，不再把未配置的内部网格当成外壳一起隐藏，并显示具体配置错误。
- 接通只读运行控制、受保护的工程师草稿预览、WebSocket 上下文，以及实际安装形态使用的 WebView 控件、标签和点位面板。离开设备视图清空拆解上下文。
- 修复 Web/Unity 的左右手坐标差异、XYZ 旋转顺序、多目标共同旋转中心、镜像实例和 X 轴裁切方向；支持负俯仰角和小部件近景。非均匀父级缩放与旋转造成的剪切会报具体配置错误，要求应用缩放或取消拆解转角，不静默变形。
- 进度、反向组装和暂停恢复采用同一时间线；编辑草稿不再让暂停的反向动画变成继续拆解，也不重置人工绕看的镜头。
- 原始 GLB 具名节点在 Three 加载/缓存克隆前恢复，避免空格、点、冒号和重复名被自动改写后与 Unity 不一致。当前平台使用自己的动作绑定，不消费 GLTFLoader 内嵌动画轨道。
- 模型首次保存不会擅自打开原来关闭的动作绑定；打包资源已包含共享模块。
- Unity 实际编辑器测试发现并修复 `MaterialPropertyBlock` 在构造/字段初始化阶段创建的异常，测试同时检查错误日志，而非只统计断言。
- 配置页保留现有工程与界面结构；调整了标签避让、网格对比度、宽屏步骤栏及隐藏文件输入，开发预览与正式构建均使用同一共享逻辑。
- 超限 JSON 在导入确认前拒绝，不会先截断再把残缺配置当作有效草稿。切换模型预览时显式释放旧 WebGL 上下文，避免长期编辑撞上浏览器上下文数量上限。
