# 低延迟优化与复测（2026-11-04）

## 已执行变更

- PLC、设备状态、选中部件数据直接使用实时响应，不再由组件刷新周期采样/复制。
- 精确点位 ID 直接查找，保留设备隔离、同角色歧义拒绝、无效/过期质量提示。
- 共享调度时钟 100 ms；HTTP/HTTP 数据集可显式设置 250 ms，SQL/业务最小周期仍为 1000 ms。
- 后端返回剩余缓存有效期，前端按该有效期读取，避免“缓存等待 + 前端完整周期”叠加。
- 快设备接口和慢业务接口分为两个有界调度通道；每通道最多一个在途批次、每批最多 20 个组件。未取消后端并发、身份校验和旧响应隔离。
- Unity WebSocket 调度先于动画 Update，在同一帧应用新目标；未改变 1 秒机械动作时长。
- Unity 诊断增加目标变化接收和首次实际变换的 UTC 时间戳，默认关闭。时间戳测量不是像素发光测量。
- WebView2 本进程禁用后台/遮挡限速；不修改系统环境或账户权限。
- 文本数值变更不再无条件触发透明窗口命中区域重算；结构/大小变化仍正常处理。
- 修复发布文档规范化隐藏的 HTTP 1000 ms 下限，避免配置写了 250 ms、运行仍按 1000 ms。

## 测量边界

同机 PLC 写入请求开始 → WS 接收 / WebView MutationObserver DOM 提交 / Unity 首次实际变换。后两者不是光学帧到光子测试。Unity 使用隔离窗口配置而非满屏现场负载；实际 PLC 扫描周期、网络和上游响应时间会额外贡献延迟。P95/最大值是此次有限样本统计，不是硬实时上限。断网重连和模型机械旅行时长单独记录。
