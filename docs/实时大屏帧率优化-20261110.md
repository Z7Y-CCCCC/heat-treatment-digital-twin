# 实时大屏帧率优化（2026-11-10）

## 本轮范围

接续 Ethan 对实际画面卡顿的反馈，处理 Unity 每帧工作量与原生 WebView HUD 刷新；不把动作语义测试当作 GPU 帧率测试。没有 Computer Use、浏览器操作、PLC 写指令、自动发布设计草稿或调整现场采集配置。

没有通过提高目标帧率、减面、改变画质档位、缩短/延长动作时序或丢弃数据边沿来制造“流畅”。普通启动不实例化测帧组件；诊断没有新增配置说明面板。

## 已消除的重复工作

- **数据批次**：设备帧仍逐条、原顺序处理，整批系统指标只聚合一次；单设备消息保留即时更新。聚合改为单次遍历，避免每批 `N + 1` 次全站扫描。动作专用更新不替换遥测对象、不把缓存重新包装成新采集。
- **HUD 时钟**：共享注入时钟，不再向所有静态卡片传递每 100 ms 变化的标量属性。需要时钟的轮播、趋势、悬停余时和提示数据轮询仍使用真实时钟；提示隐藏/预览停止读取，迟到结果不能串到新设备。
- **图表**：只订阅实际绘制输入；非趋势组件不维护无用趋势，避免无关遥测触发深度监听。
- **模型动作**：相同时间的轨迹缓存采样结果；位置、缩放和旋转核查实际 Float32 字段，确有变化才写。不能用 Unity 的近似 `==` 吞掉小位移。外部编辑、数据恢复和重配置仍重应用必要姿态；同时间的启停可见性仍切换。
- **材质动作**：区分未设置属性与显式黑色/零值，保留其他所有者的 MPB 属性。Linear 模式的颜色回读及旋转归一化使用请求值与 native 实际值双重核查，不通过放宽容差来跳写。颜色子树动态查询复用列表，仍发现重父和新增 Renderer；零转速不调用 Rotate。
- **悬停/拆解**：被 HUD 阻挡或指针不在摄像机像素区时先退出，避免无意义的全场 Renderer 扫描；恢复指针后强制重新拾取。拆解视图只写真正变化的姿态、可见性和材质参数，物料/PLC 子树的实际包围盒仍实时更新。

## 测帧工具与判定

仅设置进程环境变量 `DIGITAL_TWIN_FRAME_METRICS_PATH` 才启用。每帧固定存储、每秒聚合，落盘使用有界后台队列，磁盘不能阻塞 Unity 主线程。记录原始帧间隔、实际工厂/场景、相机及相机切换、分辨率、画质、阴影、可用 CPU/GPU timing 和绘制计数；不可用指标为 null。

```powershell
$env:DIGITAL_TWIN_FRAME_METRICS_PATH = 'RESULT_LOG.jsonl'
# 按原入口启动，正常进入大屏；保持相机、画质、窗口尺寸不变。
node tools/runtime-frame-report.cjs --input RESULT_LOG.jsonl --warmup-seconds 15 --minimum-seconds 30 --out RESULT_LOG.json
```

报告使用首个就绪连续段，预热后取首个连续至少 30 秒的窗口；不跳过坏窗口去选择更好结果。拼接原始帧数组计算整段 FPS/百分位，不能平均每秒 p95。相机/画质/焦点改变、样本缺失/溢出或不同仪器版本会拒绝比较。CPU/GPU/绘制计数是一秒一个的稀疏观测，不冒充全帧分布；测得的是普通播放器回调间隔，不是物理显示扫描时刻。

v3 每帧及 URP 渲染前核对实际主相机，旧相机仍存活、切走再切回也不会被判为稳定。旧 v2 可读，但与 v3 的比较拒绝。
