# 模型资产协作

共享基线是 `main`。模型文件在 `backend/assets/models/`，Unity 原生资产保留在 `unity-client/Assets/`；不要只互传安装包或停留在不同功能分支。

## 取得完整模型

首次安装 Git LFS，然后在仓库中执行：

```powershell
git switch main
git pull --ff-only origin main
git lfs install
git lfs pull
node tools/model-assets.cjs --check
node tools/model-assets.cjs --restore-uploads
```

也可以在 **main 且无未提交改动** 时双击根目录 `同步模型.cmd`。它只快进拉取、下载 LFS、核对清单和补齐缺失的上传副本；不同版本会停止，绝不 reset、清目录或覆盖本机模型。

## 修改后交付

1. 从最新 main 开自己的分支；优先修改共享的 `.blend`，导出相应 GLB。保留名称和模型根节点，已有引用不要随意重命名。
2. 厂房 GLB 同时用于后台与 Unity StreamingAssets，两个镜像须一起更新；检查会阻止漏改。
3. 执行 `node tools/model-assets.cjs --update`，再执行 `--check`；将模型、源工程、关联贴图和清单一起提交、推送并合入 main。
4. Git LFS 管理 GLB/GLTF/Blender/FBX 的真实内容；不能只提交一个尚未上传的 LFS 指针。CI 会下载并校验内容。

两人同时改同一个二进制模型不能自动合并：先保留两份，商定最终版本再导出，不要用“强制覆盖”处理冲突。

## 哪些不会共享

- 原始 DWG、工作副本、自动备份、重复 ZIP、渲染验收过程文件、数据库、账号及 PLC 凭据不进 Git。
- `backend/uploads` 仍是本机运行数据。已知模型别名由 `model-assets.aliases.json` 映射回共享源；恢复命令只补缺文件，不覆盖现存的不同版本。
- 新上传且还没有共享源的 GLB，须先移入 `backend/assets/models/`，更新引用和清单，不能只放在 uploads 后就认为已经分享。
- Git 同步不会自动替换正在运行的客户端或共享个人工程数据库。Unity 内置模型改动后仍需重新构建客户端；后台新模型需在各自工程中选择／导入。

新 CAD 模型可直接从各目录的 `sources/*.blend` 继续编辑。重新做 CAD 对照验收需要原始 DWG；不把只在某台机器上存在的原图当成仓库已包含的文件。
