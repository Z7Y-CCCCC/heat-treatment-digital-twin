# 报警点位约定

## 配置入口

独立“报警配置”页已移除。在“数据中心 → 点位映射”中填写点位名称、地址及数据类型，用途选择“报警触发”，同一行选择报警触发条件。

- **点位名称就是报警文本**，无需先用 bj1/bj2 编号，再单独导入文本。
- 新报警点默认 `!=0`：数值 0 / BOOL false 不触发，非 0 / true 触发。
- 同时可选择 `=0`（低电平触发）、`=1`（仅数值 1 触发）。已有数值比较条件保留原值，不偷偷改写。
- 判定的是完成数据类型转换、倍率、偏移及表达式计算后的点位值。
- 触发点必须是开关量或数值类型；文本和 PLC 日期字段不是报警触发点。

## 记录行为

采集器逐个报警点判定，状态由未触发变为触发时捕获该点的报警文本和开始采样时间；持续触发不重复记录。条件不再成立时记录结束采样时间，并补齐原触发记录，同时保留恢复事件。没有结束时间表示尚未观察到恢复。

报警状态按工厂、设备、点位 ID 独立持久化在原报警 outbox 中。多个点同时报警分别记录；重启和数据库临时故障后继续同一次报警，不重复建立开始记录。断线、异常质量、过期/缺失/无效读数不触发、不恢复已有报警，也不伪造结束时间。停用或删除点位不是 PLC 恢复，因此不补造结束时间。更名不改写已经开始的历史报警文本。

仍使用业务库 `event_logs` 和原持久化/重试流程，不新增现场业务库。点位报警的 `value` 为带 `kind: point-alarm-v1` 的结构化记录，含 occurrenceId、pointId、pointName、alarmText、condition、active、startedAt、endedAt；`/api/platform/events` 与数据中心记录接口额外返回 `alarm_started_at`、`alarm_ended_at` 等字段，时间为 ISO 格式。SQLite 事件时间按 UTC 入库，界面按本地时区显示。

普通旧设备总报警事件仍兼容；设备配置了报警触发点时不再为同一批点位另建重复总报警事件。PLC 记录字段 txt_record/date1_record/date2_record 仍保留为可读取的旧点位，但不是系统自动记录报警的前提。

## 旧数据兼容与边界

已导入的 alarm_text 在编辑器中作为报警点位名称展示；仅在用户明确保存点位时同步名称与兼容字段。内部 name、点位 ID 与既有绑定不变。既有 `=1` 等显式条件保持不变，可由用户在同一行改为“非 0 触发”。旧 `points.alarms` 权限键及只改文本的接口保留兼容，但不再显示独立页面，也不自动提升为完整点位编辑权限。

源码修改及验收只使用隔离测试目录，不重置本机现场数据库、模型、动作、默认画面模板或既有发布版本。不运行安装包/发行构建。
