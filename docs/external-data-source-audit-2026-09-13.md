原实现完成了主要页面和基本请求流程，但不能仅凭原来的“后端 26/26、前端 69/69”认定边界行为合格。复核实际发现路径拼接、健康状态可信性、异步状态、认证凭据和设计器隔离等问题，已修复并补充可重复执行的回归测试。

## 处理的问题

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| API 根地址带路径时丢失前缀 | 根地址 `/api` 配合 `/health` 实际访问错误位置，正常接口被判 404 | 根地址作为路径前缀；浏览器实测 `/api/health` 返回 200 |
| 客户端能提交任意 health，配置改变后旧状态可能残留 | 页面可能把未检查或已变化的配置显示为健康 | 仅接受服务端签发、与配置指纹匹配的短期 healthToken；修改连接清除旧状态 |
| 草稿测试、并发保存与乱序返回 | 某个配置的测试结果可能污染另一个配置或已保存连接 | 服务端校验配置修订、指纹及检查顺序；前端校验草稿版本、选择会话和列表请求顺序 |
| HTTP 重定向和原始异常字符串 | 自定义 API Key 可能被转发到跳转目标；底层异常可能回显凭据 | 不自动跟随重定向；校验请求头；错误信息和常规配置响应脱敏；及时取消响应体 |
| 编辑与认证方式切换残留字段 | 上一个连接的字段、掩码或非当前认证凭据混入新配置 | 前后端按数据源类型、认证方式隔离字段；保留、替换和清空凭据的行为明确 |
| HTTP API 出现在数据库/业务组件绑定选项 | 可以保存或发布必然无法读取的组件配置 | 设计器过滤 API；后端对草稿保存、发布、版本激活统一拒绝 API 数据库绑定 |
| 表单反馈与列表健康状态不同步 | 测试失败后卡片仍显示旧状态；部分保存/读取失败提示丢失 | 测试后静默读取服务端真实列表；未保存草稿不污染卡片；反馈不随折叠隐藏 |
| 同毫秒创建 ID 和规范化不稳定 | 新连接可能覆盖、字段重读变化影响健康指纹 | 新建 ID 使用随机 UUID；SQLite 端口、空 HTTP 状态、更新时间保持稳定 |

修复过程中同时校准了 MCP 的数据库配置调用方：数据库测试返回失败时立即终止，不继续保存、重绑组件或发布；成功保存携带 healthToken。新增真实 MCP 路由回归验证失败前后连接、草稿和发布快照不变。

数据库自动备份继续排除 HTTP API，SQLite 表/字段读取、只读公式及备份回归保持通过。没有改动现有整体浅色卡片、蓝色按钮主题，仅补充未检查状态、凭据说明和反馈布局。

- 当前页面显示“最近手动检查”的结果，不表示持续自动监控，也不证明业务数据或 JSON 映射已可用。
- 本次交付是源码修复与前端构建，没有重新制作安装包。源码运行环境需重新启动后端并刷新页面；已安装版本需更新包含这些修复的新安装包。
