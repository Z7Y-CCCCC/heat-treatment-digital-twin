# 双到位开关量：先用现有点位

## 本轮边界

只要求已经存在的两个只读开关量：**推料到位**、**退回到位**。不用先增加行程、任务号、物料检测或一大组新 PLC 点位。它们确认的是推料机构的两个终点，不是物料已经成功交接，也不是中途的真实位置。

配置入口：**模型库 → 动作动画 → 实时联动 → 选择小车 → 推料伸出 / 退回 → 到位反馈（两个开关量）**。分别从数据中心选择本设备的两个开关量，保存并同步。不能选择同一个实际点位两次；不会猜测 PLC 地址或替现场增加点位。普通范围映射、条件触发仍保持兼容。

| 推料到位 | 退回到位 | 展示状态 | 模型处理 |
| --- | --- | --- | --- |
| 关 | 开 | 退回到位 | 目标为退回端 |
| 开 | 关 | 推料到位 | 目标为推料端 |
| 关 | 关 | 等待到位反馈 | 保持最后显示姿态，不猜前进、后退、故障或成功 |
| 开 | 开 | 到位反馈冲突 | 冻结，不自动选择其中一端 |
| 任一缺失、坏质量或过期 | — | 数据无效／超时 | 冻结，不拿默认值或缓存更新时间冒充现场反馈 |

第一次读取时如果两个开关量都关闭，模型原始姿态不等于“退回到位”；界面仍明确等待确认。开关量必须是真实布尔值，并保留各自实际成功读取的时间。目录预览值不能驱动实时动作。

## 动画如何播放

沿用真实小车模型 `cad_transfer_cart_101300` 的 `feed` 动作，包括推料架、齿轮、回链及工作链条；“部件动作”预览和 Unity 使用同一动作包。实时联动配置页不再重复显示 3D 画布及本页试动作控件，数据绑定、双到位反馈、运行状况与保存同步保留；配置占满设备列表右侧空间。

获得新的唯一到位反馈后，可按已有“过渡（秒）”平滑显示到确认端。**这段过渡是画面表现，不是测得的实际推杆位置**。等待、冲突或数据失效时不推进。到位状态由开关量确认，不由动画计时结束确认。

断线／过期后，重新读取两个当前有效反馈：确认哪一端就直接对齐哪一端；两个都没确认就继续等待，不续播断线前的定时过渡。

本轮不自动把物料移入炉内、不根据“推料到位”宣告进料成功、不自动控制炉门，不写 PLC。以后确有需要时，再复用现场已有的门开、进料中等反馈扩展，不把扩展清单变成本轮前置条件。

## 新动作同步

后台“部件动作”保存模型节点动作后，现有同步消息通知 Unity 读取最新配置；设备的“保存并同步”应用该设备的数据绑定。支持的节点位移、角度、转动、显隐和变色，不需要每新增一个动作就再写一份 C# 或重新编译播放器。

**动作定义同步，不等于自动猜数据绑定**：新动作应选择正确的设备数据并保存后才跟随现场。已有点位／设备绑定、原模型文件及其他设备不应被改写。

这一轮增加双反馈协议，需要使用包含本轮运行框架的新播放器；隔离测试版不等于正在使用的旧安装版已经更新。测试不会覆盖现场安装包或数据库。

## 验收原则

- 后台实际保存双点绑定，重新读取后配置一致；运行状况继续展示真实反馈，查看或切页不隐式保存。
- 同款小车在真实 Unity 播放器验证退回、等待、推料、回位、冲突、坏质量和重连。
- “部件动作”新增／修改经过现有保存接口后，在同一 Unity 进程出现；记录进程 ID 与 EXE／程序集哈希，不能靠重启假装热同步。
- 对真实节点位置、旋转与同一动作包采样进行核对，并保留原始过程截图。
- 分别统计信号到首次模型变换、显示过渡时长及动作配置同步耗时；不把安装包构建时间当成运行延迟，不把有限样本 P95 当硬实时保证。
