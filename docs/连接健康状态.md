# 大屏与采集服务连接健康

“采集运行中心”是独立 Windows 采集服务的管理窗口，不是采集进程本身。关闭运行中心或大屏不会停止独立采集服务。

## 两侧入口

- **采集运行中心 → 概览**：大屏连接数量、最后通信、服务地址、通信说明；约每 2 秒刷新。
- **大屏 → 部署与连接**：“大屏 ↔ 采集服务”面板，分别显示接口可达性、服务端大屏实时通道和采集/数据状态；检测完成后每 3 秒复查，也可手动检测。地址编辑会重新检测，但不会自动保存或切换连接。

连接健康使用 `/api/health` 中的 `components.displayConnection`。仅统计已经通过现有 WebSocket 接入流程并声明 `unity` 角色的原生大屏，不把管理网页、健康接口查询或进程存在当作大屏在线。此处是服务端汇总连接数量，不是“当前设置窗口已经连上实时通道”的证明。

WebSocket 控制心跳每 5 秒发出，超过 15 秒没有收到通信就标记超时，并在随后心跳检查中释放失联连接。最近通信记录仅在内存中保存，服务重启后清空。场景加载/就绪与通道连通分别显示；接口可达、数据采样新鲜度、数据库、授权也分别判断。模拟或混合模拟数据有明确提示，不冒充现场 PLC。

诊断不写数据库、不改点位、不发 PLC 指令、不启停服务，也不自动降级到本机数据库或模拟模式。旧服务缺少心跳字段时显示“状态未知”，不能伪报在线。新增诊断字段不含客户端 IP、凭据或现场绑定。

## 开发验证（不是发行打包）

```powershell
node --test backend/scripts/display-connection-health-test.cjs
npm --prefix desktop run test:deployment
node desktop/scripts/native-collector-center-test.cjs
node tools/connection-health-ui-test.cjs
```

浏览器验收需要 Playwright；可通过 `PLAYWRIGHT_MODULE` 和 `BROWSER_EXECUTABLE` 指定本机依赖。原生 UI 的 `--smoke-test OUTPUT_DIRECTORY` 仅用隔离内存夹具生成截图，不读取或操作已安装的现场服务。

源码改动不会热替换已经安装或正在运行的采集程序。更新相应程序后，需要重新打开窗口/重启相应程序才能看到新版字段；不应为测试擅自重启现场服务。安装包发布仍须 Ethan 明确要求，并遵守根目录《打包必看.md》。
