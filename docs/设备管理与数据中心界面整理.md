# 设备管理与数据中心界面整理

## 设备管理

采用左侧层级导航、右侧单一设备列表：车间 → 产线 → 固定设备／辅助设备。导航显示数量，选中节点只查看该范围；车间级辅助设备及未分配设备保留入口，不会因没有产线而丢失。树和表格分别滚动，不再按车间连续堆叠多张表。

设备名称悬停可查看完整现场路径；模型预览、连接状态、最近读取和原有编辑／删除权限保留。新增设备统一放在右上角。主要名称及导航为 14px，表格为 13px，支持管理端字体缩放；窄窗口不隐藏模型功能，必要时仅在表格内滚动。

交互参考：[Carbon 层级树指南](https://www.carbondesignsystem.com/building-blocks/core/components/tree-view/guidelines)、[Fluent 2 Tree](https://fluent2.microsoft.design/components/web/react/core/tree/usage/)。参考层级分类及邻侧内容显示方式，不引入对应框架依赖。

## 数据中心

数据表、数据源、点位映射、点位监视、报警配置五个子页面移除公共的「数据中心」图标标题、简介和三步流程横幅，各子页面自身内容及左侧菜单不变。

## 100ms 的含义

设备运动页原「实时通道 · 100ms」是静态标注，并非延迟测量。后台 `/devices/:id/movement` 保存运动绑定时，会把相关点位采集周期设为 100ms；这不保证 PLC 到 Unity 画面的端到端延迟。

现改为「运动点位采集周期 · 100ms」，悬停说明保存绑定后的配置行为，以及 PLC 通信、数据传输和 Unity 渲染对画面响应的影响。本次仅修正说明，不改变采集配置或现场运动逻辑。
