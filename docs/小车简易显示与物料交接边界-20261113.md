> 后续复核见《小车进出料闭环复核-20261113.md》。进出料信号入口现统一在模型管理；旋转简模已验证并同步到 CMD 启动目录。下文末尾的早期部署记录保留为历史，不代表最新状态。

Ethan 于 2026-11-13 明确：PLC 出发前给目标工位编号，并给到位信号；没有连续位置点。大屏只需合理展示，不再要求填写现场间距、速度、加速度或补中间点位。

## 本次已实现：小车移动只用两个点位

后台 **设备运动配置**：

1. 选择本设备的 **目标工位编号（数值）**。
2. 选择本设备的 **到位信号（BOOL）**；不再额外要求到位编号和实际移动 BOOL。
3. 从当前产线导入工位，确认“PLC 工位编号 → 画布设备”的对应关系，保存。

**本页只保留一套简易表单**，没有“切换简易”“高级兼容”或旧参数入口。旧配置仅在后台和运行时保持读取兼容；打开页面只生成简易草稿，不写回原配置。保存后只保存两点绑定、工位关系和平滑选项，不再保存工位实际间距、场景单位每米、速度、加速度或旧开始信号。旧当前/最后到位编号不能自动当成目标，必须明确选择目标点位；旧移动 BOOL 也不会自动当成到位 BOOL。

轨道与工位坐标只沿用已保存的有效路径，或在用户点击导入时从产线画布读取，不在本页编辑。没有有效导轨时提示回画布绑定，不再凭空生成一段十个单位的轨道。原配置的 CAS 快照保持完整；未保存前不改变现场运行配置。旧工厂切换草稿必须重新读取后按简易方式保存，不能通过隐藏的缓存保存路径复活旧表单。

### 显示行为

- 收到有效目标编号后，按已保存的画布工位位置播放约 3 秒示意移动，不计算现场物理运动学。
- **到位时平滑对齐**默认勾选：收到有效到位反馈后，剩余路程约 0.6 秒平滑对齐；取消勾选则直接对齐。该选项保存后重新打开保持原选择。
- 换目标时，上一站保持的 `到位=true` 不确认新目标。新一程需要正常的“出发清零 → 到达置 true”；不需要新增中间位置点。
- 到位支持保持型信号，也支持**确实被采集到**的脉冲：本次目标的到位结果会锁存，脉冲回落不让小车再次离站；换目标再清除。短于采集周期且没被采到的脉冲无法靠画面补造。
- 初次启动的一组新鲜目标与到位反馈可建立初始停靠。目标变化后的到位位必须与本次命令对应，早于新命令的旧低电平也不能给新命令解锁。
- 视觉移动播完不等于真实到达；真实到位且模型完成对齐后才提供可停靠姿态。未收到到位时，仅显示估算效果，不制造完成反馈。
- 原始采集质量、来源设备、时间、到位 BOOL 类型仍校验；断线或过期冻结当前画面。未知工位不猜位置、不回退到第一个工位。
- 只读订阅 PLC，绝不向 PLC 下发控制命令。原有连续位置、旧工位估算、最后到位模式不自动迁移。

配置字段为 `displayMode: simple`、`currentPositionPointId`（目标）、`arrivalSignalPointId`（到位 BOOL）、`arrivalSmoothing`（默认 true）、工位表及轨道画布坐标。由现有运动接口和 CAS 快照保存，两个点位沿用 100ms 采集策略；新鲜度和视觉时长不是承诺的真实机械时序。

## 单设备动作：不是将 Three.js 代码转换成 Unity

导入动作包提供模型节点、动作定义和可复用轨迹；在实时联动中为具体设备绑定对应数据后，Web 和 Unity 各自读取这些定义并执行其支持的动作。标准动作不需用户重写一套 Unity 动作脚本，也不需为动画重新接一遍 PLC。

但不应把以下几件事说成同一件事：导入成功、Web 预览能动、绑定保存成功、当前安装的 Unity 播放器实际生效。任意自定义 Three.js 程序不是通用可转换动作包；节点/动作协议不支持或播放器尚未更新时，需要明确处理，不能靠导入成功宣称全部动作已验收。

## 送料、取料：现有进出料口页面统一配置

入口：**模型管理 → 进出料口 → 配置对象选择具体设备**。先选模型，再选使用该模型的设备；不是全厂设备清单。产线管理不再放进出料口配置按钮。小车、固定设备使用同一个编辑器：

- 进料／取料信号：本设备的只读 BOOL。
- 出料／送料信号：本设备的只读 BOOL。
- 可以只绑定实际具备的一侧信号；不可用点位、跨设备点位、写入点位和非 BOOL 不允许保存。两侧不要绑定同一个点位。
- 料口沿用模型默认位置与原设备微调，不增加第二组位置、距离或物料承载节点表。
- PLC 信号只保存在设备实例 loadingPortSignals；模型默认设置、动作包不含现场点位。旧坐标编辑调用不传 signals 时保留已有信号。
- 保存仍使用原 revision CAS，并保护模型身份、所属工厂和未修改的实例字段；选中的信号设为 100ms 采集。

Unity 的 SimpleMaterialTransferRuntime 只复用小车工位表里的 anchorDeviceId，查找当前真实确认且画面已对齐的停靠设备：

1. 小车出料或固定设备进料的任一有效开始沿，可驱动“小车出料口 → 固定设备进料口”。
2. 小车取料或固定设备出料的任一有效开始沿，可驱动“固定设备出料口 → 小车进料口”。
3. 不要求两侧同时为 true；实际采集到的脉冲回落后可以继续显示，保持信号不重复启动。对方稍晚的同次信号在短暂合并窗口内不重复播放。
4. 根据已有口位置和实际模型包围盒估算内部示意端点、物料大小，约 3 秒连续移动。无模型口不猜原点、不拉伸机构、不增加送料桥。
5. 送料后物料留在固定设备；取料后物料回到小车，随小车继续移动。初始库存未知时只在触发后创建一块示意物料，不凭空声称软件启动前已有料。
6. 坏质量、错误 BOOL、断线或过期不继续推进；目标改变取消未完成交接，不把旧站物料拖向新站。反向信号同时出现不猜方向；多个小车同时对接同一设备时，单独的固定设备信号不能替它们选择小车。
7. 普通支持动作包仍由原设备动作绑定执行门、推链等动作。本层只补物料连续运动，不重写动画或把 Three.js 脚本翻译成 C#。不依赖某个 CAD 模型 ID；旧严格交接状态机仍可读取，新信号配置对同一小车优先，避免双重物料控制。

所有运动/物料状态都是显示估算：不写 PLC、不修改产量、库存或实际完成记录。没有新增现场中间点位要求。项目迁移会重映射新信号与移动点位 ID，避免沿用原工厂的 ID。
