# 旧版自定义模型动画（编辑入口已移除）

2026-11-06：按当前产品要求移除“动作动画 → 工艺动作”及其自定义动画编辑器。动作动画页仅保留“实时联动”“部件动作”“设备联动”；清洗机内置工步和 CAD 部件动作继续在“部件动作”中预览，现场数据绑定仍在“实时联动”中配置。

此次不删除已有模型动作包、设备绑定或历史配置，原有包的导入、导出及 Three.js / Unity 播放能力保持兼容。下方为旧版实现记录，不再是当前操作指引。

## 旧版操作记录（入口已停用）

模型库 → 动作动画 → **工艺动作**：选择模型，点 ＋，为动作命名。

- 一个动作可包含多个模型部件；可在预览中点选，或搜索节点。拖动旋转视角不会误选。
- 支持位移、旋转、缩放、显隐和变色。位移采用模型原始单位；旋转为度，缩放为倍率。
- “行程跟随”把点位上下限映射到动作 0–100%；“运行循环”由运行信号驱动，可正向或往返。
- 可设置各部件开始/结束进度、线性/平滑过渡，旋转可指定局部转轴偏移。
- 先预览、拖动进度检查，再“保存并同步”。到“实时联动”选择具体设备、选择新动作、绑定本设备只读点位并保存。

同型号设备共用动作定义，但点位映射各自独立；新增动作默认不自动绑定、不猜测 PLC 地址、不写 PLC。坏质量、无新帧时暂停，恢复后按新反馈显示。

## 不再逐动作开发

保存时后端把配置采样成原有 portable motion schema v1，Three.js 和 Unity 读取同一动作包。新动作、改行程、调整时序都不再编辑 C# 或手改 `shared/motionPackages.json`。

**旧播放器需要一次框架更新**：之前仅允许 `/assets/motions/`，现在也允许受控的 `/uploads/models/motions/` 与迁移资产目录。SHA-256、大小限制、同源下载和禁止重定向仍保留；没有开放任意 URL。不是以后每加动作都更新 Unity。

原有 CAD 动作保留，新动作不修改源 GLB、原拆解或部件绑定。上传 GLB 的重复节点名在独立运动副本中生成稳定标识。动作源模型变更时不把旧运动副本错误套到新模型。

## 保存和携带

- 定义保存在模型 metadata 的 `motionAuthoring`；生成文件放用户上传目录 `models/motions/`，用内容哈希命名，不写安装目录。
- 预览不提交模型配置，也不广播运行端更新；只缓存同一运动模型副本，采样数据直接返回预览，不为每次预览落一份 JSON。
- 生成文件先写独立临时文件再提交；磁盘写满不会暴露半个动作包，重试可修复之前损坏的生成文件，未提交的数据库定义保持不变。
- 使用原版本校验；冲突/失败保留草稿。仍用于设备的动作不能直接删除或改变驱动方式；修改后若与其他已启用动作占用同一部件通道则拒绝保存。
- 整站备份包含生成文件；项目迁移复制 GLB/JSON、重绑定模型 ID 并重新计算动作文件哈希，不沿用失效引用。迁移后仍可编辑。

## 边界

本批适用于现有 CAD 这类节点式动作，而不是任意 Three.js 程序自动翻译成 C#。模型必须有可独立控制的节点；不能从一块焊死的网格自动推断机械结构、生成未建模的喷流/流体或求解新的复杂机构。

当前支持内嵌资源 GLB 2.0；每模型最多 32 个自定义动作、每动作 32 个部件条目，周期 0.1–30 秒，动作包上限 16 MB。相同部件的同一通道不能被两个同时启用的动作争抢；多个材质槽属于同一颜色通道。
