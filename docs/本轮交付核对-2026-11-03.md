## 1. 这次补齐的组件链路

- 数据来源主下拉只保留常用入口。既有直绑配置仍可读取编辑，但不再与数据集工作流重复并列；重复的固定设备、范围和 HTTP 刷新设置已移除。
- 数据型组件共 13 类：数值、文本、状态、指标组、HUD 指标、通用图表、HUD 图表、报警表、HUD 报警、滚动消息、设备列表、HUD 设备状态、业务摘要。装饰图片、容器、导航、返回和输入筛选属于不同用途，不强行填虚构测量值。
- 指标面板增加逐项字段选择；设备列表增加设备语义字段映射。外部数据响应可以独立完成加载，不再等待不存在的 PLC 首帧。
- 部件面板拒绝旧部件响应、异常/过期点位；有效零保持为零。切设备、切部件、定时刷新、接口失败及恢复均有短测。
- 设计器增加“读取当前设备部件”和部件选择，不再固定拿“前门组件”作所有设备的预览，也不再注入 836.4°C、1280rpm 之类硬编码样例读数。部件数据集预览使用所选真实部件 ID。
- 后台发布校验按设计稿所属工厂查连接，不再依赖调用者偶然处于某个异步工厂上下文。修复了非默认工厂独立接口“连接不存在”的问题。

## 4. 不能宣称已完成的事项

1. **所有数据源类型全部实际接通**尚未完成。现有工作台仍有明确待接入驱动，包括 Oracle、DM8、KingbaseES、GBase 8s、MongoDB、InfluxDB、IoTDB、TDengine、openGauss、BACnet/IP、HIKVISION、DIS、Excel 等；不能用图标或一个 HTTP mock 覆盖这些真实协议的验收。流协议主要仍是按需取样，不是长期全量订阅。
2. **所有 CAD 细节一项不漏**没有验收结论。五个井式炉模型元数据仍是 `review`，截图推定部分不能伪装成实测 CAD；本轮没有把该标记强改“已通过”。600 多用炉原 DWG 在原登记路径当前不可用，源文件哈希这一步无法重验，不能把 GLB 可解析当成源 CAD 一致。
3. **所有 Win10/Win11、干净机器安装/升级/卸载**没有实机矩阵通过记录；本机没有可用干净 VM。主安装 EXE 尚无厂商签名证书；SmartScreen/未知发布者不能保证消失。2.3.2 本地候选不等于 GitHub 已公开 Release，旧 v2.3.1 仍是原来的包。
4. **现场采集、长时间运行、真实硬件故障、现场 ERP/PLC**按这次测试范围没有执行，不能追加“现场全部通过”的结论。

因此，本轮是可复查的代码、配置与短测交付，不是用“全部完成”四个字覆盖上述未完成事项。需要客户设备／厂商 SDK／干净操作系统的验收应有对应证据，而不是继续静默显示成功。
