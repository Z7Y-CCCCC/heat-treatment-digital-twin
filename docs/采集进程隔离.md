# 采集进程隔离

## 运行结构

```text
Windows HeatTreatmentCollector 服务（开机运行，不随界面退出）
  ├─ 私有 MySQL
  └─ Node 管理 API / WebSocket
       └─ 独立 Node 采集进程
            ├─ PLC 协议驱动 / 模拟数据
            ├─ 各工厂采集引擎
            └─ 报警持久化与指标快照

Electron / Vue / Unity 客户端 ── HTTP / WebSocket ── 管理 API
```

前后端原本已通过 HTTP / WebSocket 分离，此次进一步隔离采集与管理接口的事件循环和堆内存。沿用已有 Windows 服务、PLC 点位和数据库配置，不建立第二套账户或设备数据。

## 稳定性机制

- 管理 API 不加载 PLC 读取器、模拟器与 DataEngine。独立进程沿用原有只读 PLC 驱动，不新增 PLC 写入。
- 采集崩溃、堆内存超限或心跳超时，仅恢复采集进程；管理接口、登录与组态仍可使用。
- 恢复采用退避（默认 1 / 2 / 4 / 8 / 16 / 30 秒，持续失败不无限快速重启）。手动停止、数据库维护及安全退出会取消自动恢复。
- 批量配置的重复重启请求会合并；加载期间新增变更只触发最新配置的补充加载，不按每个点位重复创建进程。
- 实时 IPC 最多一帧在途，按设备合并最新样本，待发队列限 2 MiB / 10000 台；单条 IPC 限 4 MiB，控制请求与缓存均有容量限制。超限样本计入 `droppedSamples`，不无限堆积。
- 报警沿用持久化 outbox，不依赖可合并的实时传输队列；指标与报警写入在采集进程进行。
- 采集退出立即广播已缓存设备的 bad 质量；无采集进程时点位监视返回 null / bad，不把上一次数值当作实时好值。原有客户端过期检查继续生效。
- 子进程没有新增监听端口，仅使用私有 IPC；不继承管理员、MCP 或桌面关闭 token，现有接口授权保持不变。
- 采集只连接已存在的数据库，不能初始化默认数据、迁移表结构或自动恢复数据库。初始化与恢复仍由管理 API 负责。
- 切换数据库和恢复备份前，等待采集进程真正退出并关闭数据库连接；不能停止时拒绝继续维护。父进程退出/异常断开 IPC 时，采集进程安全退出，避免孤儿采集与双采集。

## 诊断与操作

后台 **系统设置 → 数据通路** 显示采集隔离状态、PID 与自动恢复次数。原有“保存 / 重启数据引擎”现在只重启采集进程，不重启 API 或 MySQL。

- `GET /api/engine/status`：增加 `process`（`isolation`、`status`、`pid`、`restartCount`、`lastError` 等）。原有 mode / plcStatus / collectorStatus 保留。
- `GET /api/health`：backend 健康与 dataEngine 健康分开报告；采集异常时 HTTP 服务仍存活，展示 readiness / freshness 变为 degraded。
- `POST /api/engine/restart`：保留原页面权限校验，通过受控 IPC 安全更换采集进程。

服务级参数（整数，自动限制范围）：

| 环境变量 | 默认 | 范围 |
| --- | --- | --- |
| `COLLECTOR_MEMORY_MB` | 256 MiB V8 堆 | 128–2048 |
| `COLLECTOR_HEARTBEAT_TIMEOUT_MS` | 15000 ms | 1500–120000 |
| `COLLECTOR_START_TIMEOUT_MS` | 45000 ms | 1000–120000 |

实际 PLC 正常重连仍由驱动处理，不因单台 PLC 离线就结束整个采集进程。堆限制不等于操作系统总 RSS 限制，驱动原生内存仍需通过长稳测试观察。

## 部署与边界

- 开发：后端 `npm --prefix backend start` 会自动启动独立采集进程；前端仍单独启动。
- 安装版：重新构建安装包、更新服务资源并重启 Windows 服务后生效；仅刷新网页不会更新采集代码。客户端继续连接已有服务地址。
- 不自动改动运行中的现场服务、账号、点位或数据库；不把开发环境测试数据写入现场安装版。
- Windows 服务仍负责 API / 数据库的进程级恢复。此实现是同机进程隔离，不是将 PLC 驱动拆成无数据库的远程微服务。
- HTTP / 外部数据库组件查询仍由管理 API 按请求执行，外部数据库备份维护也保持原边界；本次隔离的是 PLC / 模拟数据引擎及其报警、指标存储，不宣称所有外部集成都已迁移。

## 验证

```powershell
npm --prefix backend run test:collector
npm --prefix backend test
npm --prefix frontend test
npm --prefix frontend run build
```

专项测试使用 output 中独立数据库与随机本机端口；验证采集崩溃/无响应自动恢复、无界面持续采集、API 保持可用、点位 IPC、手动重启、安全退出与不重复启动。所有故障注入只针对测试创建的进程。
