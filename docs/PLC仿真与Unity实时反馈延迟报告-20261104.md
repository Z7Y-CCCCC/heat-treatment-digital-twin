# PLC 仿真、Unity 动作与大屏组件实时反馈

测试日期：2026-11-04；操作对象：桌面 `大屏` 与 `PLC仿真调试器`。

## 结论

**接好真实采集点位和动作绑定后，数据与 Unity 动作可以自动反馈，不需要刷新页面或重启客户端；但目前不是所有组件都能做到亚秒更新。**

当前井式炉工程并未配置成 PLC 实采；它的接口也是本地 JSON 演示连接。此次只读核对正式配置，在 `output` 新建隔离数据库、账户、进程和本机 HTTP 接口进行测试；没有替换正式工程、默认 PLC 项目、网卡配置或连接真实 PLC。

## 二、实测延迟

时间基准为同机毫秒时钟。PLC 延迟从**发起仿真器写值请求**到收到新值；组件延迟到 Vue/DOM 提交，由页面内 MutationObserver 记录。没有把页面加载时间当作持续更新延迟。

### 真实协议采集：指定仿真器 → 大屏采集器 → WebSocket

| 链路 | 样本 | P50 | P95 | 备注 |
|---|---:|---:|---:|---|
| S7 | 24 | 153 ms | **168 ms** | 哨兵点采样 250 ms |
| Modbus TCP | 8 | 未单独汇总 | **223 ms** | 哨兵点采样 250 ms |
| OPC UA | 8 | 未单独汇总 | **215 ms** | 哨兵点采样 250 ms |

BOOL/BYTE/WORD/INT/DWORD/DINT/REAL 的 **61 组类型及边界值**通过，包括 REAL=0.125。S7 连续 20 秒收到 140 个帧，最大间隔 254 ms。协议断线、重启恢复、不同协议之间故障隔离通过。

### 实际 Unity EXE + 实际 WebView2 + 指定 Modbus 仿真器

隔离配置：点位采样 100 ms；组件刷新 1000 ms；门的过渡动作设定 1 秒。使用已有 Unity Windows 构建、真实清洗机动作包和独立 WebView2 配置目录；未使用假的 native bridge 代替此阶段。

| 阶段 | 样本 | P50 | P95 | 最小～最大 |
|---|---:|---:|---:|---:|
| PLC 写值 → WebSocket | 12 | 55 ms | **102 ms** | 12～102 ms |
| PLC 写值 → Unity 内组件 DOM | 12 | 919 ms | **2334 ms** | 754～2334 ms |
| HTTP 源值改变 → Unity 内组件 DOM | 12 | 1630 ms | **3475 ms** | 874～3475 ms |
| HTTP 请求到源服务 → 组件 DOM | 12 | 119 ms | **2018 ms** | 40～2018 ms |
| PLC → 首次观测到门动作 | 12 | 296 ms | **374 ms** | 164～374 ms |
| PLC → 观测到门动作终点 | 12 | 1298 ms | **1427 ms** | 1164～1427 ms |

**动作数据是观测上界，不是精确动作起始时刻。** 原生动作诊断每 500 ms 输出一次，本次再以 25 ms 轮询日志，可能额外增加约一个诊断周期及调度/日志延迟。动作终点还包含人为设置的 1 秒运动时长，不能全算作通信延迟。

真实门节点位移逐项与动作包插值结果比对，开/关双向通过；循环泵旋转跟随 BOOL 点位；未绑定的对照设备保持静态。13 种数据组件族接入并渲染，实际数值、metrics、KPI、趋势读数持续更新。未配置数据库连接的业务摘要仍提示未配置，不伪造业务库验收。

模拟器停止后，Unity 机械位姿与运动相位冻结；原生测试中首次收到坏质量为 5524 ms、首次观察到冻结为 5539 ms，重建模拟器至观察到恢复后的门动作终点为 11137 ms。上述计时包含进程停止/启动及重连，不是网络黑洞的纯检测时间。组件保留最后读数但明确显示“离线/数据延迟/正在同步”，**不会清空所有最后读数**。HTTP 503 时数据集组件停止显示旧的有效读数，恢复后自动继续更新。

## 三、为什么组件比 PLC 慢

1. 采集与组件刷新不是同一个周期：100～250 ms 采集不等于 100～250 ms 更新所有组件。
2. `WidgetRenderer.vue` 的设备读数按组件 `refreshMs` 采样，`useWidgetClock` 为 1 秒 tick；测试早期保留默认 5000 ms 的 PLC 数值组件，实际约等了 5 秒。改成 1000 ms 的测试配置后，仍受页面调度影响。
3. `widgetReadScheduler.js` 前端定时读；`dataSets.js` 与 `dataSources.js` 后端缓存也按刷新周期过期。刚好命中尚未过期的旧缓存，会再等一个组件刷新周期。**1 秒设置不保证 1 秒端到端，5 秒设置可能接近 10 秒。**
4. 同一台机器同时运行 Unity、WebView2、图表与采集服务，也会产生调度抖动。测试是隔离/后台客户端及 DOM/变换诊断，不是全屏电视的光学帧到光子测量。

此轮只测量并添加测试工具，**未修改产品采集/缓存逻辑或正式工程设置**。建议后续先完善井式炉点表和动作绑定，再对缓存/前端轮询作同步调度或变化推送；生产任务旧接口优先迁移为统一数据集。不要仅缩短采集周期就承诺大屏延迟变小。
