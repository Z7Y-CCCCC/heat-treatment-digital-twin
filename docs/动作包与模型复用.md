# 动作包与模型复用

动作包不是单独的动作配置文件。单模型 ZIP 含源 `model.glb`、模型配置清单和部件动作；有已编译动作时还含 `motion.glb`、`motion.json`。合集把多个这样的模型目录放进一个 ZIP，不含现场数据库、PLC 点位或设备实例配置。

## 导入流程

1. 选 ZIP 后先检查包完整性和当前工厂可见模型。
2. 弹窗逐项显示结果：**新建模型**、**复用已有模型**、**更新已有模型动作**。
3. 确认导入；模型在检查后发生变更时，拒绝过期计划，点击“重新检查”再确认。

相同文件及相同有效配置不会再新增模型。源 GLB、缩放、放置层级、拆解布局、进出料口或独立配置不同，则视为独立模型，不按名称强行合并。同源且非动作配置一致时，优先原模型 ID 或导入来源 ID；存在多个无法确定的旧候选时拒绝自动覆盖。

## 更新动作会影响什么

确认后只替换模型层 `partBindings`（包括其动作数据绑定）和随包提供的动作资源；引用该模型的设备会使用新动作。共享模型的更新影响引用它的所有工厂，检查弹窗明确提示此范围。

模型名称、源 GLB 路径、工厂归属、缩放、类型、标签、缩略图、进出料口、拆解布局和其他独立配置保留。设备实例、设备 PLC 点位及设备间联动配置不变。缺少随包编译动作文件不代表删除已有编译动作。更新编译动作仅写新的不可变 `motion.*` 文件，不再复制 `model.glb`。

## 重试与回滚

- 成功请求的重试记录指向实际复用或更新的模型 ID，返回其当前状态，不把旧包重新覆盖到后来编辑的新动作上。
- 同一个请求标识不能改用另一个 ZIP。
- 合集任一项失败，全批模型和动作更新回滚，清理本批新建的动作／模型文件。数据库提交状态无法确认时保留文件，避免误删已提交资源。
- 旧客户端未提交明确更新计划时不能覆盖已有动作。

本功能阻止新的重复导入，不自动删除历史重复模型。已存在的重复项需另行核对引用和差异后清理。
