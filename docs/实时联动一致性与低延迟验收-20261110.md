# 实时联动一致性与低延迟验收（2026-11-10）

## 目标与边界

本轮接续 Ethan 的现场大屏需求：实时大屏、后台动作预览使用相同动作数据、相同坐标与来源语义；料车与固定设备的物料交接跟随真实承料节点，不以另造工艺时间轴、延长行程或移动目标设备来模拟“联动成功”。

现场设置放在正常后台配置中，不能依赖修改代码、手工改数据库或另外添加来源说明面板。旧工程、采集地址、模拟/实时模式和 317 组件未发布本地草稿不自动迁移、不自动发布。

本轮没有 Computer Use、真实浏览器操作或 PLC 控制指令。内存 Vue 测试、隔离 HTTP/SQL、实际 Unity `-batchmode -nographics` 是不同层次的测试，不能冒充现场 GPU、视觉流畅性或 PLC 到屏延迟验收。

## 配置入口

- **产线管理 → 产线结构/轨道**：设备线与料车轨道的间距（米）、场景单位/米；设备中心距按该比例换算。所有已有轨道端点和工位统一移动，失败整事务回滚。确实会被 JavaScript 舍入或 Unity Float32 吞掉的非零位移明确拒绝，不人为替换位置。
- **移动设备 → 移动设置**：本设备当前位置/当前工位反馈、目标工位命令、启动点位、工位间距及移动效果。目标命令不能冒充实测停靠。没有显式移动比例时显示并继承所属产线比例，不写入隐藏配置。
- **模型库 → 动作动画 → 实时联动**：本设备只读数据源、范围/条件/双到位、过渡时间；同一页面配置实时进出料联动的送料动作、承料节点、物料存在反馈、固定或当前工位目标、两端进出料基准、物料米制尺寸与偏移、停靠/交接限制。
- **模型原有进出料口/部件设置**：提供真实模型基准、位置动作通道及转速比例。错误或缺失基准报告不可交接，不自动挪车、伸长推料器或把目标变成移动设备。

旧产线未声明新比例时，原有移动显式比例继续按原值读取。下一次有关保存按当前完整单位合同检查：若原值是 0.8、产线有效默认值是 1，需要操作员在上述现有入口明确统一校准，不静默“修正”工程。

## 连贯性和还原性修复

1. **跟随实际位移**：物料以承料节点实际父变换和实际位移为依据；米制尺寸、半高、镜像/倒置及目标模型热更新保持 Web/Native 合同。健康来源物料是否可见，与目标是否允许交接分开。
2. **来源有效性**：保持原点位身份、质量、源采集时间、缓存年龄、乱序和连接世代；重复包装不会成为新采集，断线/坏质量/超时冻结，恢复不重放虚构动作。
3. **关键变化不被 latest 吞掉**：BOOL 边沿、已配置 WORD 启停、条件穿越/回差、工位枚举和转速停转/变向形成合并屏障；同态连续值仍只保留最新原值。不能把所有数字 0/1 猜成开关量。
4. **真实转速语义**：部件 `rotate_speed` 使用原数值、真实 Float32 比例、配置速度与反向，区别于 clip 的运行阈值。没有实例动画配置才继承模型；显式空/禁用不会复活。继承源批量按本设备 READ 点位及精确 group/key/ID 匹配，缺失、歧义和外厂归属不猜测。
5. **有界过载恢复**：两端队列保持完整离散快照、连续 latest 和来源时钟；超过内存/数量边界后重连并重新同步，不无限积压，也不伪造漏掉的历史。
6. **局部故障隔离**：转速或旋转步长溢出不进入 Unity Transform；显式 JSON-null/标量/数组动画声明停用其动作，不再在模型加载入口索引异常并使整个工厂反复重建。它们仍是坏声明，不等同“缺字段继承”。
7. **范围一致**：动画接口、数据中心、运行上下文与语义缓存统一 primary → railLineId → laneLineId → workshop 归属优先级，外厂关联不能用本地车间覆盖来“救回”。
8. **启动不改作者配置**：已校准的 v2/local 工程跳过重复空间迁移；混合旧工程只迁移待处理对象，不重复舍入其他设备坐标、翻转 ±π、重序列化已有 JSON 或丢弃扩展字段，不新增迁移 marker。备份预算在金额和来源未变时保留原文件、配置时间及扩展字段。

新完整热链路的第一批回环验证覆盖 9×120 个观测、2160 个动作目标，以及离散边界、同态 burst/latest 和旧源时间戳重复包装。其 P95 为 89.865 ms，包含探针验证开销和当时全机重负载；实际输入节拍没有达到 100 Hz。**它不能与旧未接语义链的 P95 直接比较，不能代表现场 PLC/GPU 延迟，也不是动画机械到位时间。**
