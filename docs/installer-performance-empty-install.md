## 源码改动

### 减少落盘与重复复制

1. 后端依赖仅裁剪非运行类型声明/TS、source map 与普通文档；保留许可证、版权通知、二进制、JSON、证书，以及 package main/bin/exports/browser 显式声明的运行入口。实际依赖文件数 **19,933 → 9,791**，少写 **10,142 个文件（50.9%）**。归档固定 mtime，策略源码纳入缓存指纹；主程序按归档 SHA-256 而非安装时间判断是否需要重新展开。采集 worker 本身已有内容摘要缓存，新归档也因此能跨相同依赖版本的升级复用。
2. 插件直接发布通过完整清单和 SHA 验证的、管理员拥有的同盘 staging，不再做第二份全量复制。没有跳过源目录、安装结果或主包的插件一致性验证。
3. 主包沿用 stock electron-builder 主脚本，在 stock installer.nsh 加载后覆盖 I/O 宏：用同一 Nsis7z 解码器在安装盘的独立目录解压，核验文件/目录清单后目录级发布。保留卸载器生成/签名、归档大小检查与最终 EXE 全树解压门禁；不设置自定义 nsis.script，因为它会绕过这些正常构建路径。
4. 本产品没有 electron-updater，不再把完整安装器写入无用途的 updater 缓存（原包约 833 MiB）。若以后增加 autoUpdater/electron-updater，构建必须失败，先审核缓存/更新策略，不能静默省略。
5. 升级不再逐文件搬到 TEMP，而是用同盘目录重命名留存旧程序供回退；正常卸载只对清单核验后的程序文件使用原生目录删除。未知文件/目录、改过的配置、链接、系统/源码根与现场数据重叠均拒绝处理。清理中断可安全重试；已提交升级的回退清单保留在被删除目录之外，不能恢复部分删除的旧版。

这些是落盘工作量与控制流改动，不等于已经测出了新 EXE 的实际安装/卸载秒数。旧 v2.3.4 卸载器不会因为源码变更自动升级；首次从旧版交接仍可能走旧卸载逻辑。

### 空白安装与升级明确区分

- 升级默认沿用原服务 root/端口，不覆盖旧工程。
- 向导增加“新建空白现场（旧工程原目录保留，不删除模型或 PLC 配置）”。选择后服务切换到新建的机器级 collector-empty-GUID 目录；旧目录不删除。静默参数为 /WITHCOLLECTOR=1 /NEWEMPTY=1，修复重试不重复创建空白工程。
- 无服务配置的首次安装，不自动导入 APPDATA，也不隐式恢复卸载残留的旧目录。独立插件的原工程迁移必须显式指定 ImportDataDirectory；它与空白模式互斥。
- 新现场仍只拥有静态模板；工厂、设备、模型、动作包、PLC、数据源、账户及业务记录需用户另行配置/导入。大屏卸载保留独立采集服务和现场工程，这是独立采集的既有约定。

### 日志与等待

- 自有 PowerShell 子进程固定 UTF-8；最外层 nsExec 使用 UTF-16LE，BOM 与首行合并写出，统一流式读取后用 Console 输出。sc.exe/icacls.exe 按 OEM 代码页解码，再输出 Unicode。
- 按批次排空 stdout/stderr，不能人为每行休眠 50ms。日志带阶段 elapsed；真实 warning、stderr、失败返回码和超时保留。
- 服务 pending 状态以定期进度显示代替 PowerShell 自动重复 warning，避免重复 Start/Stop。保留 60 秒停止预算、900 秒启动预算及 HTTP/数据库/collector ownership 的实际就绪检查，不能仅 Running 就报告业务就绪。
- 安装子进程恢复 Windows PowerShell 5.1 自带模块路径，避免继承 PowerShell 7 的模块路径后找不到 Get-FileHash；摘要检查仍必须成功。路径属性检查使用 Force 读取隐藏目录，拒绝源码子目录、现场目录双向重叠及链接。独立插件提权只转发明确的导入路径，不传空字符串参数。

### 英文 Windows CI 跨环境回归

首轮 GitHub Windows 资源门禁发现 TEMP 使用 `RUNNER~1` 短路径与 Windows PowerShell 5.1 长路径展开不一致；隔离夹具现在使用实际临时根和 `realpathSync.native` 身份，所有严格路径、现场保留与防误删断言不变，清理前再次核验根目录真实身份。

英文 OEM 437 不能表示中文，原生 `icacls` 可能在输出字节前将文件名替换为问号。按 OEM 解码不能还原上游已经丢失的字符，因此自有日志明确输出已知 ACL 目标的 Unicode 上下文，原生 stdout/stderr 不伪造、不重写、不隐藏；不记录其他任意命令参数。原有中文目标断言保留，并增加完整目标与文件未变断言。新增独立 OEM 字节探针按当前代码页选择可表示的非 ASCII 字符，验证原生字节边界而非错误地要求 CP437 输出中文；包含原始字节与错误码交叉验证，不接受替换问号。

跨环境修复后，两组完整专项 **17 项通过、0 跳过**。全部默认资源门禁增加至 156 项，需在本机及 GitHub 再次完整执行成功后才能合并和发行；不降低模板、空数据、签名、完整性或就绪门禁。
