## 本轮交付

在原「设备动画联动」配置和「产线设备联动」预览中接入显示模式，没有新增正式业务页面。Unity 原生实时运行时已接入相同规则；Three.js 与 C# 分别渲染。

适用于已配置明确出料口、相对设备口、真实承料节点、唯一工位和只读 BOOL 的小车交接。`handoffMode: adaptive` 必须显式启用。旧配置仍为原机构行程模式；本轮不修改已保存的操作者产线、草稿、采集器或安装包。

### 核心行为

1. 布局仍使用单侧上排、单侧下排、双侧设备线及既有红框。
2. 独立示意桥覆盖车口到炉口的显示间隙；原 CAD 和 1.085 局部单位行程不变。新增桥不表示现场存在这段机械结构。
3. 物料连续经过精确炉口，落到真实内部承料节点；取料沿相反路径回车，同一物料只显示一份。
4. 独立停靠和源／目标在位 BOOL 为确认依据；时长只估算中间动作。缺少确认保持等待，陈旧／断线／命令改变／路径改变冻结显示。
5. 自适应只解除原机构行程覆盖间隙的上限，不绕过方向、高度、横向、工位或承料节点检查。

## 验收边界与回滚

- 验证的是小车／回火炉真实样本及通用交接规则。不能把它宣称为所有炉型、升降／横移机构的通用碰撞验收。
- 炉门使用独立绑定，在验证中先以虚拟 BOOL 打开。此改动没有增加新的现场炉门安全联锁，也不使用通用碰撞规划器。
- 真实后台链路使用虚拟只读来源，不测真实 PLC／采集器的端到端延迟，也不等于整个现场大屏的 FPS 验收。
- 暂存构建已验证，但未安装／覆盖操作者当前应用，现有配置未自动选用自适应模式。
- 回滚时先停用循环或改回「原机构行程」，确认原行程可达，再恢复旧配置／应用备份。不要为消除提示而放宽几何公差，不改数据库连接、草稿或现场点位。
