# 开发交接与仓库约定

协作入口：<https://github.com/Z7Y-CCCCC/heat-treatment-digital-twin>，以 `main` 为基线。不要继续从旧 backup 分支开始新任务。

## 1. 源码与运行文件的区别

- 正式三维大屏：`unity-client`；桌面宿主：`desktop`；WebView2 宿主：`native-admin-host`。
- 后台与预览/手工拆解：`frontend`；配置与数据采集服务：`backend`；独立采集服务：`collector-service`。
- 保留前后端和桌面的 `package-lock.json`，使用 `npm ci` 复现依赖。
- 仓库不带现场工程配置、数据库、账号、PLC 密码、安装包或构建 EXE。新克隆需构建，不能直接双击启动脚本。
- 五台井式炉保留最终 `.blend`、`.glb`、`.fbx`、材质、Prefab、审阅场景和参考图。这些是可继续编辑的模型资产，不是缓存。旧型号运行 GLB 保留用于已有配置兼容；不要因版本号较旧就直接删除。

## 2. 环境与依赖

Windows 完整客户端需要 Node.js 22 LTS（至少 22.12.0）、.NET 8 SDK、Microsoft Edge WebView2 Runtime，以及项目指定的 Unity 编辑器及 Windows Build Support。

当前 Unity 版本见 `unity-client/ProjectSettings/ProjectVersion.txt`：**2022.3.34f1c1 / URP 14**。未经验证不要升级项目。Blender 只在重新建模时需要，井式炉脚本使用 Blender 5.1。

```powershell
git clone https://github.com/Z7Y-CCCCC/heat-treatment-digital-twin.git
cd heat-treatment-digital-twin
npm --prefix backend ci
npm --prefix frontend ci
npm --prefix desktop ci
npm --prefix mock-server ci
```

## 3. 先启动后台开发（不接现场数据库/PLC）

新终端在项目根目录运行：

```powershell
$env:DB_TYPE = 'sqlite'
$env:APP_DATA_DIR = Join-Path (Get-Location) 'backend/data/dev-local'
$env:SQLITE_FILE = Join-Path $env:APP_DATA_DIR 'factory.db'
$env:HOST = '127.0.0.1'
$env:PORT = '3001'
npm --prefix backend start
```

另一个终端：

```powershell
npm --prefix frontend run dev -- --host 127.0.0.1
```

打开 Vite 输出的 `/admin` 地址，首次设置本机测试账号密码。后台可以开发与预览，完整工厂三维运行仍需要 Unity；旧网页 `/` 入口已弃用。离线展示要在后台选择模拟数据模式，不要填写或连接真实 PLC 地址。

代码默认数据库仍是 MySQL；这里显式使用隔离 SQLite。若要测试 MySQL，应使用独立测试实例和环境变量，不复制现场 `database-config.json`，更不要使用现场 root 账号做测试。

## 4. 构建完整桌面客户端

先安装上述工具；必要时通过 `UNITY_EDITOR_PATH` 指定实际 Unity 编辑器路径。然后：

```powershell
npm --prefix frontend run build
node desktop/scripts/build-unity-client.cjs
node desktop/scripts/build-native-admin-host.cjs
```

完整构建成功后运行项目根目录的 `启动大屏.cmd`。它使用 Electron 宿主，不要只双击 Unity EXE。桌面宿主使用独立用户数据目录及其中的数据库配置，不继承上面后台开发终端的临时配置；根据启动页面进行本机配置。安装包需要额外的资源准备、私有 MySQL 和发布步骤，见 `desktop/README-交付说明.md` 与发布脚本；不要将生成文件提交进源码树。

## 5. 提交前验证

```powershell
node tools/repository-hygiene.cjs
npm --prefix backend test
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix desktop run test:logs
npm --prefix desktop run test:processes
npm --prefix desktop run test:resources
```

Unity 坐标/拆解对照（需要编辑器）：`node tools/native-device-inspection-layout-checks.cjs`。
实际客户端冒烟：`node tools/native-client-smoke-test.cjs`。这些验证使用隔离副本，输出在 `output/`，不等于现场 PLC、GPU 或真实断电验收。

## 6. 不提交的内容

`.gitignore` 排除依赖、`dist`、Unity Library/Builds/UserSettings、.NET bin/obj、`output`/`logs`/`tmp`/`temp`、模型工作副本/自动备份、验收截图和报告、数据库与备份、实际 `.env`、私钥与现场配置。

仅往 `.gitignore` 加规则不能移除已经跟踪的文件；用 `git rm --cached` 只取消跟踪，保留本机副本。本次清理沿用这种方式。历史中的旧模型备份仍可通过旧提交恢复，没有强制重写 Git 历史，也没有删除旧协作分支。

`node tools/repository-hygiene.cjs --history` 可以检查可达历史中的高可信令牌/私钥特征。扫描不输出密钥值，不能代替人工审查或服务端 secret scanning。代码里的回环演示数据库默认值和隔离测试 fixture 不是现场凭据；生产环境必须独立设置。

## 7. 工作方式

```powershell
git switch main
git pull --ff-only
git switch -c codex/任务名
```

每个任务在自己的分支开发。保存源码、测试与必要文档，不提交个人测试数据。测试前确认数据库与端口属于测试环境。不要改写共享 `main` 历史。
