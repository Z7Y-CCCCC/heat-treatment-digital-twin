# Windows 打包加速

正常入口仍为项目根目录的 `生成安装包.ps1`、`生成安装包.cmd`，或 `npm --prefix desktop run dist`。

- Unity 先完成场景生成，随后前端、后台宿主、采集服务与采集运行中心最多同时执行两个任务。资源准备只等待后台宿主，可与前端构建重叠。最终运行验证和安装包压缩仍等待所有必要组件完成。
- 采集组件按源码、编译工具和输出内容校验缓存，采集服务还检查还原后的 NuGet 依赖记录。发现损坏、缺失或多余文件会重新编译。编译失败或源码在编译中改变时保留上一份完整缓存。
- 采集运行中心禁用机器默认 `csc.rsp`，显式固定并校验 Framework 引用；编译子进程使用同一份只读环境快照。完整环境仅以 SHA-256 摘要进入缓存身份，不保存环境值。与编译无关的环境变化（例如候选目录改变）也可能造成保守的额外缓存失效，以避免漏掉 MSBuild 的自定义环境属性。
- 前端缓存只读取一次完整输出目录，继续检查内容损坏和多余文件。只改安装页 PNG/BMP、原生布局或安装脚本时，已有完整验证记录可走界面重打包流程；第一次构建、程序改动或缓存已清理时仍需完整准备。
- 各组件日志位于本次候选目录的 `component-build-logs`，阶段耗时记录在 `component-build-timings.json` 及总报告 `build-timings.json`。并行阶段耗时存在重叠，不能直接相加作为总耗时。
- 构建调度器默认继续输出中文状态与错误。隔离测试注入局部日志记录器并逐条校验这些消息，避免 Windows 上原始控制台文本与 Node 测试报告的二进制帧混流；编译器输出文件、环境转发和失败断言不变。

## 极速压缩选项

需要尽快生成本地交付文件、可以接受更大体积时，在项目根目录运行：

```powershell
.\生成安装包.ps1 -FastPack -NoPause
```

`-FastPack` 将主程序的 7z 归档级别设为 0。普通模式采用原生 7z，默认低成本级别 1；显式指定 3–9 时使用 BCJ2 二进制过滤器。环境变量 `ELECTRON_BUILDER_COMPRESSION_LEVEL` 可指定 0–9；`-FastPack` 优先使用 0。独立采集插件 ZIP 默认级别 3，仍逐字节验证内置副本。运行验收使用工作区归属标记的唯一临时目录和互不重叠的私有 MySQL 端口区间，在保留全部检查的前提下并行。详见《安装包大小与速度优化-20261117.md》。

极速模式保留数据库迁移、首次启动、采集组件、空系统检查、源文件绑定及安装资源 SHA-256 校验，不替代这些检查。界面重打包只能复用已通过完整验证、源码内容相符的程序。

需要忽略采集组件缓存时，设置 `DESKTOP_FORCE_COLLECTOR_REBUILD=true` 后构建。原有 `-ForceUnityBuild`、`-RefreshDependencies` 和 `-FullBuild` 保留原有含义。

修改打包脚本不会自动生成正式安装包；整体打包耗时应以完整构建的 `build-timings.json` 报告为准，不能将单个组件或压缩样本的提速比例当作整体提速。
