# 设备数据播放与 WebView 图表

本次把现有采集缓存、设备上下文、数据集与定时刷新串成统一配置，不另建采集服务，不由控件直读 PLC。

## 配置

设计器选中数据控件，在「设备数据播放」设置：

- **固定设备**：总览中显示指定设备。
- **设备轮播**：选多台设备，分别设置切换间隔和数据刷新间隔。
- **跟随视角**：按工厂／车间／产线范围取设备，多台时轮播。
- **设备、透视、拆解和部件视角**：锁定该视角的当前设备，不继续播放其他设备。

数据集通过设备上下文传参／匹配；PLC 点位按当前设备的同类点位映射。数据库、HTTP 直绑和排产业务摘要也使用同一个设备播放配置；业务能耗／维护表没有可匹配设备列时不回退为全厂记录。不存在、重复或跨工厂的目标不回退成其他设备的数值。有效零值保留；失败和缺值不伪造成正常或零。

一个画面使用一个调度器，最多每批 20 个控件；复用原有后台缓存。切换时取消旧请求，卸载后停止刷新。设备时钟不进入数据缓存身份；时间戳更新但数值不变时不重建图表。

## 图表与材质

20 种真实渲染类型：折线、平滑折线、阶梯折线、面积、堆叠面积、柱状、横向柱状、堆叠柱状、折柱组合、饼图、环图、玫瑰图、仪表盘、散点、雷达、漏斗、热力、K 线、箱线、瀑布。

数据集可选多个数值列；热力／散点、K 线与箱线有对应字段映射。雷达需要至少三个数值维度。历史曲线按设备隔离，最多 32 份历史、每份 240 点；不生成虚假的历史／预测数据。

WebView 运行卡片、地图／场景内置面板统一为紫色半透明材质，后台表单保持浅色。文字不通过整体 opacity 淡化。CSS backdrop-filter 可模糊同一 WebView 内的背景，**不能模糊另一个进程中的 Unity 像素**；没有为此增加昂贵的持续截图复制。

## 井式炉现有展示

移除「视频监控」信息列表，不将摄像头清单伪装成视频流。对以前自动生成且带 `pitStaticDisplay: 1` 标记的画面，读取时统一为设备参数、状态、温度趋势、生产任务及部件信息；总览轮播九台井式炉，设备视角跟随当前设备。辅助设施只显示设施信息，不显示炉体工艺参数。

这是幂等、可回退的展示升级：保留原始草稿／发布快照、自定义控件、几何、PLC 地址、采集模式和外部连接；用户保存／发布时才写入新画面。未删除外部数据源连接，也未更改现场采集开关。

## 本机加载时发现的登录重发

本机运行核验复现了旧宿主的管道问题：Unity 读完并关闭管道后，`StreamWriter.DisposeAsync` 再次 flush，产生已断开管道异常；发送端把它当作发送失败，重发已消费的一次性登录凭据。后台正确拒绝重放，但 Unity 因第二次交换失败退出已成功的登录。

宿主改用不带缓冲的单次管道写入，写入完成后的 EOF／断开／回执超时不再重发同一凭据。保留现有同用户管道检查和后台一次性票据验证，没有放宽认证。隔离测试包含确定性的旧错误复现、断开回执和真实命名管道，连同原生覆盖层共 50 项检查通过；仅重建原生宿主，不涉及安装包。
