# 运行资源热点修复（2026-09-30）

本轮承接同日资源复查，修复拆解拾取、日志增长、备份峰值及实时投影/消息积压四项。模型、材质、纹理、阴影、特效、分辨率、渲染帧率及 PLC 采集周期均未降级。修改的是重复计算、I/O 路径和队列管理。

## 实现

### 精确拾取

- 静态网格按原始三角形建立共享空间索引；仍使用逐三角形的精确相交计算，不以包围盒代替部件。
- 鼠标、相机、可见性、网格和模型变换均不变时复用悬停结果；PLC 位移、拆解/裁切进度和蒙皮变形继续触发计算。
- 轮廓高光仍逐帧绘制。共享索引用弱引用关联网格，模型释放后可回收。

### 日志

- `admin-host.log` 改为后台有界写入：活动文件 10 MiB，最多 5 份归档，30 天清理；目录锁协调多个宿主的写入与轮转。
- 小车普通位置变化默认不写日志；显式开启诊断后每 5 秒采样。运动位置和更新时机保持不变。
- Electron 日志轮转采用异步文件操作及流式 gzip。磁盘故障、退出和部分写入都有测试覆盖。
- 极端故障下超出队列容量的日志会丢弃；恢复后写入丢弃/恢复摘要，避免 UI 因日志卡死。

### 备份

- 资源快照以流式异步 I/O 同时复制并计算 SHA-256；ZIP 输出同步计算整包哈希，减少额外全量读取。
- 已压缩图片、视频和 gzip 文件在 ZIP 中直接存储；GLB 等仍按需要无损压缩，不改变资源内容或精度。
- 数据库默认预算 2 GiB、整站默认预算 4 GiB。未显式配置的旧默认一起迁移；保留运维显式预算。
- 执行前按实际磁盘合并数据库转储、快照、ZIP 临时文件和镜像的空间需求，并预留空间。完整备份成功之前不为腾空间删除旧恢复点。
- 预算是轮转目标：为保留最后可恢复备份，单份超预算时可以超过目标；临时文件、现场资源和外部镜像需要另计。无法读取策略时保守保留并报告，不擅自覆盖显式设置。
- MySQL 旧包不会仅凭 gzip 文件头标为完整校验通过；后台列表区分“已校验 / 已损坏 / 恢复时校验”，未校验包仍可下载并在恢复前严格验证。

### 投影与消息

- 缓存模型 Renderer 集合和拆解部件静态描述，每次仍读取实际变换、边界和可见性，保持原投影周期。
- WebSocket 出站和 Unity 入站设置消息数量与字节预算。只合并相邻的可覆盖状态；配置/控制和质量故障作为顺序边界。
- 超限或长期阻塞时明确断开并重连，随后重新读取权威配置；浏览器地图、HUD 和大屏覆盖层也补齐重同步。
