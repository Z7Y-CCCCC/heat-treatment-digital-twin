# 车间编排：三处编辑入口合并

## 用户界面

- 唯一菜单为 **车间编排**，继续使用 `composer` 权限标识以兼容现有账户。
- 菜单位置为 **工厂建模 → 设备管理下方的车间编排**，顺序为车间管理、设备管理、车间编排、设备运动配置，不再占用一级入口。旧服务仍返回一级菜单目录时，客户端也按新位置显示；权限、工作台草稿与保存逻辑不变。
- 不再显示“现场编排器”“产线管理”菜单，车间管理仅保留 01 车间列表、02 空间与边界；03 产线布局及原画布已移出。
- 同一工作台提供对象树、车间总览／产线聚焦、俯视排布／三维效果。不是把三个页面纵向堆叠。
- 画布固定在视口内；对象树、属性栏独立滚动。窄屏对象树为抽屉，属性栏浮在画布内。
- 三维视图继续使用原模型加载与预览实现，复用绑定的真实模型，不另做模型选择或低模覆盖逻辑。
- 自动排布只提供单侧／双侧及单侧位置选择；先展示按真实模型包围盒计算的方案，确认后进入草稿。可以取消、撤销，双侧独立计算间距。
- 自动排布只计算设备排与小车导轨的对接间距；每台设备的左右 X、设备顺序和已配置线长均原样保留。同排左右位置由用户拖动，或主动选中后应用间距，不做自动压紧、居中或展开。若原有同排模型相交，只提示用户手动调整。
- 俯视排布工具栏常驻“未摆放设备＋数量”，收起后仍可展开。设备栏占据工具栏下方的横向区域，不再依赖旧浮窗位置或画布底部；设备多时横向滚动，不纵向撑高页面。未摆放设备不参与自动间距计算或被自动绑定。
- 正常操作中不显示红色校准区域、批量进料面／高度对齐按钮。没有可靠几何或机构可达区间时报告原因，不缩小模型、不拉长机构。
- 对接预览复用 `DockingCalibration`，在工作台中是只读模式，读取已有模型料口、使用当前草稿位置，不能保存实体位置或发 PLC 指令。
- 设备优先在三维画布用移动轴／水平转向环调整，“精确输入”作为右侧折叠后备。保留标高和地面跟随既有行为；模型身份仍在设备管理维护。

## 草稿与保存

- 设备移动、设备池分配／移出、间距调整和工位编号编辑在工作台中都只修改内存草稿。
- 切换俯视／三维、进入／退出产线、切换对象不会要求分别保存，也不把未保存草稿推送到正式 Unity 大屏。
- 顶部“保存布局”提交 `PUT /api/workshop-arrangement`，同一数据库事务提交产线位置／结构、窄设备变换以及地面修改。
- 后端先核对全部来源快照、工厂归属和字段白名单，再写入。任一步失败整批回滚；并发变更返回 409，前端保留草稿。
- 产线结构、车间内产线位置、设备变换和地面仍分别检查原有权限，合并菜单不授予额外编辑权。
- PLC 网络参数、点位、动作绑定、料口、模型身份不在新接口的可写字段中。移动整条产线只改父级变换；设备本地坐标和工位编号不会因此重写。
- 新增／删除产线前须处理未保存修改，避免生命周期操作重新加载数据时冲掉草稿。

## 已配料口但朝向不相向的只读检查

- “料口未配置”与“已配置但朝向不相向”分开处理。读取双方保存的型号料口、实例微调及整车变换，不把同口进出误判为漏配，也不假设切换进／出料口一定能解决。
- 车间编排的只读对接预览遇到已知方向异常时，仍显示两个真实 CAD、真实料口位置及蓝／橙方向箭头，明确标注哪一方背向；默认切到俯视检查，不再只留下红字与空画布。
- 不自动反向料口法线、换口、翻转整车、伪造转台、重选区域、改变模型比例或改写现场数据。小车沿原导轨临时停到所选工位的 X 位置仍仅为预览姿态。
- 方向异常时不显示绿色“已对齐”，毫米偏差仅供检查，不能由诊断方案生成保存请求。可编辑校准保留严格方向检查；真实缺少料口／模型等错误仍阻止伪造预览。
- 方向为各料口的水平外法线，不是进料运动矢量。“都已配置”并不代表它们在当前设备朝向下已面对对方。
- 前端全量 2104 项及 10 项浏览器流程通过；浏览器验证等待真实模型加载完成和俯视按钮可用后截图，不以空 WebGL 画布作为通过依据。
- 已发布到本机界面网关，核对当前入口 → AdminAccess → AdminPanel 的实际引用链及脚本摘要；后端 PID 不变，现场配置写入为零。最新成功记录为忽略目录 `output/workshop-arrangement/frontend-docking-inspection-update-1794671034220/`。
- 本次修复诊断预览被阻断的问题，不等于已替用户校正真实小车送料端／整车朝向；不会将朝向异常报告成可完成机械交接。
