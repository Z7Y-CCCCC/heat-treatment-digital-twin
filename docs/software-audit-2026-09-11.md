## 结论与交付边界

后续使用用户指定的 PLC 仿真调试器加强测试，另发现并修复了 REAL/LREAL 过早舍入问题。三协议七种类型的 61 组边界数据均通过；详见 [指定仿真器加测报告](plc-simulator-validation-2026-09-11.md)。下文保留首轮排查结果与隔离异常记录。

本轮完成了运行时、后台管理、数据库与备份、采集链路、前端生命周期、Windows 桌面监督、Unity 客户端、交付资源准备和辅助 MQTT 模拟器的代码检查、异常复现、修复与回归。

修复已经落在当前源码及依赖锁文件中；前端生产构建、NativeHost 构建和 Unity 实际 Windows Player 条件分支的 C# 编译均通过。没有覆盖既有安装包，没有部署到现场，也没有提交 Git。检查开始前已有大量未提交修改，本轮在其基础上增量修改，未回滚原有工作。

这不是“软件绝对不存在任何潜在问题”的保证。真实 PLC、物理断电、长时间运行、Unity GPU、多屏和正式安装升级仍需现场验收。已有安装包和打包资源中的二进制不会因源码修复自动更新，发布前必须重新构建。

## 已修复的问题

| 范围 | 原问题与影响 | 修复及回归重点 |
| --- | --- | --- |
| SQLite 事务 | 并发事务相互冲突；普通写入可能加入另一请求的事务并被其回滚吞掉；读取可能看见未提交数据 | 连接访问队列、事务上下文隔离、过期事务禁写、关库等待；并发 upsert 使用原子操作 |
| 数据库切换 | 保存坏配置后才尝试连接，失败可能使原数据库、采集和备份不可用 | 先预检，再停维护并切换；初始化失败恢复原配置、连接、采集和维护 |
| 数据库预检 | 查询失败未释放连接；SQL Server 预检可能使用运行主连接；错误服务可能无限等待 | 独立连接池、驱动层连接/查询超时、失败清理与销毁 |
| 批量设置 | 后续字段校验失败时，前面字段已经写入 | 先验证全部输入，再在事务内提交 |
| 备份与恢复 | 并行切库、恢复、导入和其他管理修改互相干扰 | 维护操作互斥；停止并等待在途自动备份；慢速上传完成时重新检查维护状态 |
| 恢复点保留 | 保留数为 1 时，恢复前的额外备份可能清理掉用户选中的源备份 | 源备份先受保护，使用恢复函数内的回滚备份；增加真实 HTTP 保留数为 1 的恢复用例 |
| 整站灾备 | 异地清理误删同目录其他 ZIP；回滚失败后原件仍可能被清理 | 仅清理本站命名的备份；回滚失败保留原件并报告路径 |
| 灾备包解析 | Windows ADS、设备保留名、尾点及大小写重名等路径边界 | 校验危险路径与重复项；拒绝不属于本软件结构的 SQLite 恢复库 |
| 外部数据源备份 | 输出流/压缩流失败可能成为未捕获异常；重复备份和停用后重启任务 | 使用完整 pipeline 错误处理；按连接合并任务；停止等待全部在途工作；坏 SQLite 提前拒绝 |
| 设计器持久化 | 错误场景 ID 静默回退；相同修订的并发保存互相覆盖；组件 ID 可跨场景抢占 | 显式 ID 严格匹配、修订 CAS、场景归属校验；发布切换/删除增加并发条件检查 |
| 采集器生命周期 | 快速启动、停止、重启残留采集器、定时器或迟到连接 | 取消过期启动、隔离旧回调、关闭迟到连接；并发重启只保留一个数据源 |
| PLC 数据质量 | 空 Modbus 响应和非有限数值被视为正常；旧读取回调影响新请求 | 地址与响应校验、异常数据标坏、读取代际隔离、OPC/Modbus 取消清理 |
| 报警与统计 | 报警并发重复记录；坏质量伪造恢复；分批 PLC 帧统计不全 | 事件串行写入、恢复质量校验、按全体设备统计 |
| 报警时间 | SQLite 的 UTC 裸时间被当作本地时间，显示差 8 小时，一小时筛选漏掉最新事件 | SQLite API 输出明确 UTC ISO 时间，窗口参数按 UTC 存储语义计算；不重解释其他数据库的裸时间 |
| 后台会话 | 锁定期间已经开始的密码验证仍可产生新会话；过期窗口可能假确认全部锁定 | 锁定撤销在途登录；过期凭据明确拒绝；前端允许重新认证但不假报成功 |
| 跨窗口/断网锁定 | 其他窗口可能在服务器确认前重新显示后台；未知网络结果被误当成功 | 区分待确认和已确认；断网保持编辑界面关闭并显示重试提示；监听器可清理 |
| 点位编辑 | 空字段变成 DB0.DBW0；旧设备响应覆盖新设备；复制后归属错误 | 缺失值校验、请求代际保护、复制清除来源 ID 并重新归属 |
| 点位保存 | 初次读取失败可保存为空表；重复提交；保存期间的新编辑丢失 | 拒绝不完整加载后的保存、合并重复保存、保留保存期间的新草稿 |
| 运行设置 | 周期轮询覆盖未保存端口、PIN 和开关 | 运行状态与用户编辑草稿分离 |
| 实时前端 | 重复 WebSocket、卸载后回写、离线设备仍计运行、空温度计为零 | 幂等连接、请求取消、状态/质量过滤、生命周期清理 |
| 三维与音频 | 模型加载中退出后访问已销毁场景；音频离开页面仍播放 | 过期异步结果回收、资源释放、停止音频和语音回退 |
| 图表与组件 | 切图型残留旧 series、尺寸变化不重绘、DOM 更换仍用旧图表、精度越界崩溃 | 替换图表配置、观察容器尺寸、重建图表、约束精度和缺失数据状态 |
| 后台缓存页面 | 隐藏页面轮询和快捷键仍运行 | 停用时停止任务与监听，激活时恢复，避免重复注册 |

## 可重复执行

使用 Node 22 LTS（至少 22.12.0）及 .NET 8，安装相应目录锁定依赖后：

```text
npm --prefix backend test
node backend/scripts/run-tests.cjs --with-plc-simulators
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix desktop run test:logs
npm --prefix desktop run test:processes
npm --prefix desktop run test:resources
npm --prefix mock-server test
dotnet run --project tools/native-runtime-tests/NativeRuntimeTests.csproj --configuration Release --artifacts-path output/native-runtime-tests
dotnet build native-admin-host/HeatTreatmentAdminHost.csproj --configuration Release --artifacts-path output/native-host
```

`--with-plc-simulators` 需要相邻 PLC 仿真调试器和 Python 依赖；不具备时只执行常规测试。MySQL 灾备测试必须显式配置专用测试服务，不再默认读取现场配置。依赖审计使用 `npm audit --registry=https://registry.npmjs.org`，镜像不支持 audit 不能解释为“没有漏洞”。
