# 进出料门体等待

## 原因与行为

动作包的 `door` 轨迹不等于“相位 1 必然开门”：有的模型初始门已抬起，动作反而将门落下。此前录像脚本统一写入 true，也未由物料层检查门体是否让开，因此可能出现关门时物料穿过门板的画面。

- 从动作包已有 `door` 轨迹收集实际门体网格，复用三角形空间索引，沿当前完整交接路径检查物料截面。依据真实门体姿态而不是统一的信号极性判断通道。
- 门未让开时不创建交接物料、不消耗已有请求，相关辊筒保持停止；门打开后沿用原请求连续交接。
- 中途门关闭时保持同一件物料的位置；重新让开后继续，不重新生成或跳转物料。
- 等待中的持续信号仍须实时有效，不虚构上升沿／新采样时间；短脉冲保留原等待窗口。信号过期、连接中断和工位变更等原有规则不变。
- 隐藏门的渲染或改变透视材质不会让物理门体检查消失；普通可见部件拾取仍按原可见性判断。空心门框按实际三角形而非包围盒阻挡。
- 无 `door` 动作的开放料台不增加门条件；有门定义而网格不可核验时保持等待，不默许穿门。

沿用已有动作包、料口、门动作点位及进出料信号；不新增表单、现场距离或加速度参数。此逻辑只约束大屏动画，不下发 PLC 命令，也不替代现场安全联锁。

## 回归

`TransferDoorClearanceValidation.Run` 包含 56 项真实 Unity 断言：正常与反向门动作、旋转／镜像／非均匀缩放、关门等待、长时间持续信号、部分开门、中途关门再继续、隐藏渲染、空心门框、缺失／不可读网格和无门料台。原有辊筒／对齐、工位移动、物料连续交接及旋转车检查保持原断言。

可选的隔离验收探针提供门实际位置、源采样时间和只读通道检测；不启用探针的正常客户端不写验收文件。现场库、配置导出、录像及构建文件不进入 Git。
