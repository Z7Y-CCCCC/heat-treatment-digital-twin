# 工厂语音播报与移动保存提示 · 2026-11-05

## 页面

- 设备运动配置：保存成功、校验失败、HTTP 失败均使用顶部气泡，不再插入整行提示推开表单。相同错误可再次提示；保存时禁止重复提交和切换设备；原有草稿与原子移动保存接口不变。
- PLC 点位映射：“语音播报”表头增加工厂胶囊总开关。只改当前编辑工厂，不改其他工厂、采集开关和点位规则；读取/保存失败不会假报成功。只有点位编辑权限可操作，读取账户不能修改。
- 开关存入现有 `factory_settings.voice_enabled`，没有增加数据库或依赖。未配置时保持原来允许播报的行为。专用 GET/PUT `/api/settings/voice` 返回明确 factoryId；旧后台没有该接口时不会把开关误写成全局设置。

## 实际链路与修复

实际使用的 Unity 透明数据层此前只有设计器 `play_voice` 预览/事件入口，没有将 PLC 实时点位交给自动播报器。现在集团地图、街道/厂房、Unity 透明数据层都复用各自已有的 DataStore/WebSocket，不新增轮询或第二条数据连接；后台地图预览不发出自动播报。工厂配置的语音点位单独包含待布局设备，避免只依据已摆放模型导致漏报。

工厂开关通过 `factory_voice_changed` 实时生效，不重载 Unity 场景。关闭会清空等待队列并停止当前播报；恢复后只处理新的有效变化，不补播停用期间的旧变化。其他工厂的数据、乱入的全局帧、无效和过期点位不触发；断线恢复先建立新基线，避免“坏值变 0”误报。处理中到达的旧配置响应不能推翻刚收到的工厂开关状态。

- 相同点位元数据复用已编译规则，不在每个 PLC 帧重复解析所有规则。
- 同一规则播报中不重复入队；等待中的同规则使用最新上下文。最多等待 16 条、15 秒，过期语音不积压到几分钟以后；**这只清理语音通知，不清理报警记录，不改变采集**。长语音本身仍有自然播放时间，不能把串行语音保证成每条同时立即播放。
- 最多复用 4 个音频元素，配置阶段仅预取本地音频元数据，不无界下载/缓存全部声音。
- 文件启动预算 1500ms；坏文件或启动卡住会转系统文字播报，单条失败不停止后续队列。实际播放另设完成看门狗，不用“首次加载一直等 30 秒”阻塞全部消息。
- 自动播放策略受浏览器控制，不能将 `play()` Promise 当成已出声；记录实际 `playing`/TTS `start`。普通浏览器被策略阻挡时保留有时效的通知并等待用户手势。原生 WebView2 宿主仅给本应用进程加入自动播放参数，不更改注册表或系统浏览器策略。

### 延迟测量边界

隔离 Chromium、静音输出、本地回环 WAV，24 次真实 HTMLAudio 播放，计 `play` 请求到 `playing` 事件：冷启动约 **226.6ms**，整体 P95 **1.4ms**，最大值为冷启动值；该小样本只有一次冷启动，其余为缓存路径，**不代表所有电脑、更不代表 PLC 到扬声器的端到端延迟**。

故意卡住的真实音频请求约 **1502.8ms** 后进入文字播报回退，下一条仍可处理；此回退测试使用可控 TTS 回调，不把它当作声卡或 Windows TTS 的实测耗时。现场总延迟还包括点位采集周期、WebSocket 传输、已有语音播放时间和系统音频设备；没有为追求数字而擅自降低全部点位采样间隔。

证据保留于根目录 `output/voice-motion-ui-*`、`output/voice-feature-*` 和 `output/page-permissions-http-*`，不上传现场数据。旧宿主备份记录在 `output/voice-local-update.json`。
