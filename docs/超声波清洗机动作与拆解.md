# ultrasonic_cleaner_cad 动作与拆解

第一阶段提供门体升降和气缸轴随动，以及 9 个可编辑的拆解总成。使用 CAD GLB 原始节点，无需重新导出模型。模型及默认配置随仓库提供，新克隆仓库也能直接选择 `ultrasonic_cleaner_cad`；已有工厂同名模型和保存布局优先保留。

- 动作信号：`doors.front_door_open`，BOOL 的 false 为关闭、true 为打开；全行程时间 3 秒。CAD 原始位置为抬起状态，局部 Z 关闭端为 `-0.686`、打开端为 `0.22`，行程 `0.906`；关闭端完整覆盖门口，打开端留出通道。
- 动画预览按同一门信号联动门板和随动机构；可点击“关门到位 / 开门到位”静态检查两个端点。
- 运动节点：气缸轴、接头、门框架、门体、门滚轮、轴销、连板共 20 个节点。CAD 装配局部 Z 对应导出模型的竖直 Y，所以配置使用 Z 轴。
- 固定机构：气缸本体、固定座、门导轨、下部导向轮；不把整套门装配连同固定部件一起抬起。
- 拆解分组：升降门、固定气缸与导轨、框架辊座、水槽、电机风扇、分离系统、震板、喷淋管组、加热器。可在模型库继续调整偏移、时序和镜头。

当前行程、时间和拆解位置均为展示示例，不能当作现场标定或检修规程。电机风扇节点包含外壳，未将整个总成错误地旋转；真实风扇动画需先分出转子。超声波震板未使用可见的大幅抖动模拟超声频率。真实 PLC 地址尚未配置。

完成依赖与 Unity Windows 客户端构建后，在仓库根目录运行 `node tools/multipurpose-motion-demo.cjs --model-id=ultrasonic_cleaner_cad` 打开独立模拟演示；关闭 Unity 窗口会停止该演示后端。演示数据库位于 `output/cad-motion-demo-*`，只保留一台设备，复制当前模型与配置进行验证，不改现场设备记录。存在本机上传版本时优先使用该版本，否则使用随仓库提供的 CAD 模型。

模型配置脚本为 `tools/configure-ultrasonic-cleaner.cjs`，通过本机后台 API 保存并先备份原模型元数据到 `output/ultrasonic-profile-*`；登录密码仅从环境变量 `MODEL_PROFILE_PASSWORD` 获取，不保存到源码。`--calibrate-door` 只更新该型号的 20 条门联动端点，并保留已有拆解布局；后端地址可通过 `MODEL_PROFILE_ORIGIN` 指定。

验证：运行 `node --test backend/scripts/ultrasonic-cleaner-profile.test.cjs`，默认读取随仓库提供的模型，检查真实 CAD 坐标下的竖直运动、固定件不动及门口遮挡；也可用 `CLEANER_GLB` 指定另一个模型文件。运行 `node tools/multipurpose-motion-demo.cjs --model-id=ultrasonic_cleaner_cad --check` 验证 Unity 模型、部件解析、开关信号和授权回归。

加 `--packaged-model` 可强制从仓库随附模型启动，不读取本机上传数据库，适用于新环境验收。
