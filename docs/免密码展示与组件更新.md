# 免密码展示与组件更新

实时大屏使用独立只读展示身份，不输入后台密码也必须加载模型、画面和实时数据。后台管理、编辑和现场操作仍按账号权限校验；此功能不创建管理员、不保存密码，也不替代许可证激活。

## 三个独立组件必须一致

- `启动大屏.cmd`：检查并按源码更新网页、Unity 客户端、WebView2 原生宿主和运行中心界面。构建失败停止启动，不回退旧界面。此过程不是生成安装包。
- 独立采集服务：Windows 服务运行的是其安装目录中的后端代码，不是工作区后端。更新 GitHub、网页或 Unity 均不代表该服务已更新。更新已安装服务须明确确认、备份程序代码、短暂停采，并保留现场库、资产和配置。
- 安装版：使用同一套展示会话协议与启动门禁；未来构建须从同一源码构建前端、Unity、宿主及配套采集服务。旧安装包不会因源码更新自动变新，不得在用户未要求打包时重新发行。

后端健康接口公布 `capabilities.displayStartup`：`version: 1`、`passwordRequired: false`、`readOnly: true`。客户端先检查协议再启动 Unity；旧服务应明确提示需要更新，不能让操作员面对一直停在 0% 的加载画面。该门禁只检查能力，不自动升级、重启、连接第二个采集器或修改现场数据。

## 验证

```powershell
node --test desktop/scripts/display-startup-test.cjs desktop/scripts/desktop-supervisor-unit-test.cjs backend/scripts/display-bootstrap-test.cjs
npm --prefix frontend test
node desktop/scripts/verify-default-dashboard-template.cjs
```

真实 Unity/WebView2 隔离验收：在 `output` 下准备当前源码编译的 `player`、`AdminHost`、`frontend` 三个目录，然后运行 `tools/native-display-autostart-test.cjs --stage <绝对暂存目录>`。额外使用 `--configured` 验证已有账号但没有登录 Cookie 的站点，使用 `--slow-startup` 验证慢响应。测试不输入密码、不登录，确认场景就绪、加载罩退出、管理写入被拒绝，且账号未被改写。禁止用真实现场目录当作测试数据目录。

出厂模板和空现场数据要求继续以根目录《打包必看.md》为准。

## 加载阶段与导入调度

- 原生首次查询先建立展示 Cookie，再读一次会话；不先请求匿名会话，也不在根组件重复建立已成功的展示身份。
- 初次透明层尚未获得展示身份不等于退出登录，不抢占为密码页。服务短暂失败后，通过已确认的恢复事件自动继续；用户主动打开后台时不抢回大屏。
- 尚未收到原生进度时明确显示“连接中”，不把未知等待伪装为百分比。展示会话交接到现场加载保留已完成的 6% 阶段，不再归零。最终 100% 仍要求真实场景与网页共同就绪。
- glTF 导入使用每次异步续执行后的 8ms 合作式工作预算，避免当帧其它启动工作已经耗尽默认预算而反复空等下一帧。仍定期让出主线程，保持完整几何、动作、拾取、超时和取消机制；不采用阻塞式整模型导入，也不修改现场模型包。
- `ModelTemplateTiming` 记录导入、实例化、优化各段耗时，`ModelLoadTiming` 继续记录单设备实际总耗时，便于区分网络、模型与拾取索引瓶颈。
