# 平台缺陷、复用闭环与构建审计

日期：2026-09-29。范围：当前工作区，保留原有 MySQL 安装交付改动。所有编辑与数据库回归均使用隔离测试环境。

## 本轮目标与验收口径

工程师不改源码，可以配置组件和多级视角、绑定已有数据、预览、保存草稿、发布、恢复历史版本、导出设计模板，在目标场景导入并重新绑定当前工厂实体。并发保存和发布不得丢稿、误发旧稿或产生重复版本；多个工厂可以独立应用示范配置。发布构建应排除历史前端产物、复用有效缓存，保留失败日志与阶段耗时，并通过随包数据库首次启动验证。

“所有 bug 已消除”无法由有限测试证明。本报告记录实际发现、修复及验证范围，不把未实测硬件和长时间稳定性视为通过。

## 已修复的缺陷

1. 保存接口返回时覆盖期间新增编辑；修订冲突自动重载导致草稿丢失。
2. 并发发布生成重复版本号，或在草稿更新后发布旧修订。
3. 同一秒发布多个版本后，运行最新版本误选旧快照。
4. 空运行文档投影抛错；父级、返回及混合视角导航成环。
5. 新工厂的默认导航组件 ID 与已有场景冲突，第一次保存失败。
6. MCP 低代码配置遗漏工厂上下文；直接创建拓扑遗漏归属；示范 ID 在多工厂间冲突。新增双工厂重复应用验证。
7. 导入和撤销后分辨率选择框不同步；发布提示错误宣称未连接 Unity 已收到更新。
8. 安装版第一次解压后端依赖时 Windows 目录重命名失败。增加有限占用重试、等待解压进程完全关闭、事务发布和旧目录恢复。
9. 原生 WebSocket 回归测试未跟随可选参数变更，反射调用失败；已恢复实际取消与连接替换测试。

## 新增复用闭环

设计器提供导出模板、导入模板和实体引用重绑定。导入保留目标项目/场景身份；设备、点位、数据源、产线和车间引用须显式映射到当前工厂，校验失败保留原稿。点位显示所属设备与中文名称，PLC 路径和单位随目标点位更新；导入可撤销，不会自动发布。

真实浏览器已完成：导出 → 导入带源客户引用的模板 → 错配点位被拒绝 → 正确绑定 → 保存发布 → 再导出核对 `Furnace_01 / 1 / analog.actual_temp / ℃`。浏览器无错误日志；截图在 `output/playwright/platform-published.png`。模板格式及操作限制详见 [闭环审计](platform-closure-audit-2026-09-29.md)。

后续已补齐项目 ZIP：导出受支持的工厂配置、拓扑、草稿/发布记录、模型和本地引用资产，校验后创建独立新工厂并重映射 ID 与资产路径；包括 glTF 外部依赖和内置模型资源。工厂级设置随项目迁移，集团地图外观和加载画面由用户显式选择是否应用，默认不覆盖共享设置。导入不携带 PLC 地址/连接选项及数据源账号，采集关闭、以模拟模式启动，保留原工厂。

数据库/API 的复用不再只停留在替换连接 ID：设计器“重绑定数据”读取目标表字段或响应路径，提供同名预填与候选映射，必须逐项真实数据预览并确认含义才应用。整站灾备增加迁移项目资产、外观资产、工厂数据源及备份选择的恢复覆盖。使用流程见 [项目迁移说明](project-bundle-migration.md)。

## 构建根因

开发目录保留历史 chunk，而发布直接收集该目录，是最明显的输入膨胀来源：前端发布输入从 494.64 MiB / 3,323 文件变为约 43.84 MiB / 537 文件，减少 91.1%。这不是完整安装包或总耗时减少 91.1%。

发布改用独立干净目录，保留开发热更新兼容；FFmpeg 解压、原生后台发布、后端依赖 tar 均有可失效缓存；依赖安装根据锁文件与运行时指纹判断。双击与 npm 构建使用同一路径，执行程序目录生成、首次运行 MySQL 验证、NSIS 压缩，并输出 `build-timings.json`。详细测量见 [构建性能审计](../tools/BUILD-PERFORMANCE.md)。
