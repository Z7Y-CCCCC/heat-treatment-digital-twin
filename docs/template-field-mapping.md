# 模板数据字段迁移

设计器的模板导入现在分两步：先选择当前工厂的设备、点位和数据源，再映射数据库或 HTTP API 字段。导入过程保留原草稿，取消不会替换布局。

## 操作

1. 在设计器导入 `.dashboard.json`，完成设备、点位、数据源等引用绑定。
2. 对每个数据库数据项选择目标表。系统读取目标数据库的真实表和字段，支持数值、时间、排序和上下文筛选字段。原字段名完全一致时预填；常用别名、末级名称和兼容类型仅作为候选，所有字段都可手动选择。
3. 对 HTTP API 检查目标 GET 路径，读取实际响应字段和示例值。可直接选择候选，也可手填发现列表之外的深层或数组路径；后端实际读取会验证该路径存在。
4. 对每个数据项点击“预览实际数据”，核对字段含义、单位及结果，勾选确认。空值不代表故障，但仍需核对数据源在当前上下文中是否确实无数据。选择发生变化后原预览和确认自动失效。
5. 完成全部确认后载入草稿。检查组件显示，再保存并发布。数据库别名和公式保持原定义，映射后的字段写入正式数据绑定；后续运行不依赖导入弹窗或浏览器内存。

完整项目 ZIP 导入后，在工厂选择器切换到新工厂，先配置目标数据源，再进入画面设计器点击“重绑定数据”。该入口直接以当前草稿进入同一向导，无需再次导出 JSON。当前工厂已有的设备、点位和层级 ID 自动预填，迁移时隔离的 `unconfigured_*` 数据源必须选择已配置的新连接，再逐项映射字段、预览并确认，最后保存发布。

数据库预览使用当前设计器上下文，固定设备组件使用映射后的设备。数据集的 `contextField` 和 `contextKey` 保持配对；时间、排序或筛选原本设置过的字段必须明确映射，避免迁移后悄悄丢失筛选条件。

## 自动匹配范围

自动候选依据字段名称、常用中英文别名、目标字段类型；它无法替代业务语义确认。例如“温度”可能代表设定值或实测值，因此非精确候选不会静默应用。数据库必须能够查询元数据；HTTP 发现遵循现有后端的响应大小、深度及字段数量限制，发现范围之外可手填路径并实际预览。

`business` 模式是内置业务汇总协议，使用固定业务区块而非任意字段路径，仍通过数据源 ID 绑定迁移。自定义业务数据应选用数据库或 HTTP API 模式。

模板本身仍是布局和绑定文件；模型、图片等文件资产迁移使用项目迁移功能。

## 回归验证

`frontend/tests/template-field-mapping.test.mjs` 覆盖候选匹配、类型冲突、任意字段选择、筛选排序映射、真实元数据接口调用、预览确认、HTTP 手填路径和过期响应隔离，以及复制组件内部可见性事件目标重映射。

`frontend/tests/data-source-designer.test.mjs` 覆盖导入前草稿保护、ID 到字段两步衔接、撤销、字段映射期间草稿变化拒绝、保存映射结果后再发布，以及弹窗键盘不修改背景草稿。

HTTP 端到端集成可执行 `node frontend/scripts/template-http-e2e.mjs`。脚本只在 `output/` 下创建独立数据库，启动真实后端和本机 HTTP 数据源，并运行生产 `TemplateFieldMapper.vue` 的实际 setup/确认逻辑（不渲染浏览器）。API 传输指向真实测试后端，没有模拟 inspect/preview 返回值。脚本验证接口和 JSON 路径同时变化、原接口错误显示、确认门禁、保存发布及已发布运行接口；再改变上游数值，验证运行结果独立刷新而不是复用向导预览。结束后关闭所有服务，留下 `report.json` 和 `backend.log`。
