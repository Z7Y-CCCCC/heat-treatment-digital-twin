> 后续实现已按 Ethan 要求改为 **C# WinForms 原生小窗口**，不用 Electron、WebView2 或浏览器内核，界面简化为状态、日志两页。本文保留调研时的方案，实际交付与验证以《采集运行中心-验收清单》及最终执行记录为准。

## 结论

Ethan 的描述可以归纳为：**Windows 常驻采集服务 + 独立运行管理界面 + 可查看、可导出的日志**。

这是成熟工业软件采用的形态，不需要让一个黑色终端长期挂着，也不应该靠大屏窗口活着才能采集。建议保留现有采集架构，补齐一个轻量“采集运行中心”，而不是重写 PLC 驱动或另建一套后台。

本报告是调研与源码核查成果，**不是新功能已经实现的说明**。本轮未安装、启停或修改现场服务，未变更账户、点位和数据库，也未推送 GitHub。原聊天中的拆解拖拽复查与推送仍是另一项尚未完成的操作，不能算作本报告已完成的工作。

## 3. 建议做成三个清晰的入口

### A. 后台服务：不显示窗口

- 安装后开机运行，不依赖登录，不依赖 Unity 或浏览器。
- 用户关闭运行中心或退出托盘，不停止服务。
- 单台 PLC 断线只恢复该设备连接，不重启全部采集。
- 采集进程故障由 API 内监督恢复；API/数据库托管链故障由服务宿主和 SCM 恢复。界面要区分这两种“恢复次数”。
- 保留现有只读采集、安全退出和现场数据路径，不为新界面再起第二个后端。

### B. 采集运行中心：独立小窗口

优先复用现有桌面安装包和 Vue 技术栈，提供本地打包页面，不加载 Unity、不启动 3D。不是复制一份完整后台，也不是要求用户每次进系统设置找状态。

**总览**

- Windows 服务：未安装 / 已停止 / 启动中 / 运行中 / 停止中 / 无法查询。
- 管理接口：可达 / 不可达；数据库：正常 / 故障；采集：正常 / 部分异常 / 停止。
- 模式：现场 PLC / 模拟，必须显著标注模拟状态。
- 已启用设备、在线设备、有效/过期/坏质量点位、最后采样时间。
- 工作进程运行时间、恢复次数、最近故障；CPU/内存指标只有新增真实采样后才能展示。
- 展示端未连接是可选状态，不应仅因为 Unity 没启动就把“采集总览”判为故障。

**设备**

提供设备名称、协议、连接状态、实际采样间隔、最近成功时间、失败原因和点位质量；所有数值来自现有配置和采集遥测，不填演示数字。

**日志**

提供最近日志、时间范围、级别、组件和设备筛选、暂停滚动、复制、导出。默认先展示警告和错误，点击可看完整上下文。服务启动、恢复和停机信息独立于业务报警。

**操作**

- 打开完整管理后台、查看/导出诊断。
- “重启采集进程”沿用现有授权接口，只影响采集。
- “启动/停止/重启 Windows 服务”明确说明影响整个服务链，经过 OS 权限检查与确认；手动停止不应被界面偷偷重新拉起。
- 启停后的确认来自实际 SCM 状态和就绪检查，不能点击按钮就显示成功。

关键约束：**服务停了，运行中心也必须能打开**。本地壳通过受限系统查询获得 SCM 状态；API 不可达时明确显示离线并使 API 操作失效。日志与启停不能完全依赖已经停止的 API；可使用经过 ACL 限制的本地桥接/提权帮助程序，只暴露固定服务操作和固定诊断导出，不接受任意命令或任意文件路径。

### C. 托盘：可选，不作为第一期前提

登录后显示一个托盘图标，菜单仅包含“采集运行中心 / 管理后台 / 导出诊断 / 退出托盘”。图标状态依据实际采集健康，托盘退出与停止服务是两件事。第一期先完成可靠小窗口，托盘是便利项。

## 4. 日志应简单，但不能失控

- 结构化事件至少含 UTC 时间、级别、组件、事件代码、工厂/设备标识、消息；界面转换为本地时区，并保留可导出的原始时间。
- 默认 INFO/WARN/ERROR；DEBUG 按组件临时启用并自动过期。
- 正常日志记录状态变化，不逐点每 500 ms 输出。重复断线错误合并，并保留次数及首次/最近发生时间。
- 复用现有默认单文件 10 MiB、归档 30 天/60 个/250 MiB 策略，同时审查各类日志合计上限；服务宿主目前另有 previous 文件策略，不能把上述配额说成所有文件的绝对总上限。
- 磁盘满、无写权限、日志写入失败都要可诊断，但不能导致无限错误刷屏。
- 诊断包包括必要日志、版本、SCM 状态和组件状态；限制大小，去除密码、令牌、私钥、连接串秘密，不默认带数据库、模型或完整现场配置。

## 5. 最小交付顺序与验收门槛

1. 运行中心总览：先接已有健康/进程状态，补齐本地 SCM 查询及停机可打开路径。
2. 服务与工作进程两类操作：加入权限、确认、真实结果和操作审计。
3. 日志结构化、限量查询、筛选和脱敏诊断包。
4. 独立设备状态页与可选托盘；不先做复杂远程运维或重写驱动。

验收至少覆盖：

- 新装与升级后的服务注册、低权限启动、端口冲突、启动失败、卸载保留数据。
- Windows 重启且无人登录时的真实采集；用户注销、锁屏、关闭 Unity/运行中心均不停止服务。
- 仅对隔离测试创建的进程注入采集崩溃、API 崩溃、单台 PLC 断线；分层恢复且无双采集/孤儿进程。
- 手动停止后不自动复活，恢复操作不绕过维护/备份中的停机约束。
- SCM 显示运行但 API 不可达、API 返回 200 但数据过期、模拟模式、未启用设备等状态准确，不全部显示绿色。
- 普通用户可获授权诊断，不可随意启停服务或读取任意系统文件；API 不可达时仍能本地诊断。
- 日志轮转、磁盘满、中文路径、诊断包脱敏与导出上限。

现有 console smoke 不等同于 SCM 注册、无人登录、真实断电或现场 PLC 验收。
