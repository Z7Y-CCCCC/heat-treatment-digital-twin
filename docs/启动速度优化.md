# 启动速度优化（2026-11-04）

## 已改

- 根目录 `启动大屏.cmd` 不再每次运行 Vite。先比对前端、公共资源、共享配置、依赖锁文件和 Vite 环境的内容指纹，并重新校验实际入口、懒加载块和资源。无变化才复用；源码变化、文件缺失/损坏或缓存损坏仍重新构建。
- 并发点两次启动时共享构建锁；失败不写成功标记，构建途中源码变化会中止。保留旧的内容哈希块，不删除正在使用的大屏仍可能请求的文件。没有加后台监听进程。
- 源码运行已有配套 `backend/node_modules` 时直接使用，不再给每个运行账户/测试目录重复解压归档。**正式安装版不借用工作区依赖**，其随包准备和完整性检查不变。
- 激活通过后，将首次系统设置读取与 Unity 启动并行；仍等待设置与 WebView 就绪才确认完成。轮询合并为单个在途请求，接口慢时不叠加请求。等待期间 Unity 意外退出会报启动失败，不能误报就绪。
- 去掉加载小窗的固定 120 ms 等待，只让出一次事件循环。没有改动画时长、伪造进度或取消激活/环境/数据库检查。

## 本机实测

使用隔离 SQLite 测试账户目录、实际桌面宿主、Unity 与 WebView2，终点是登录入口就绪；**不是 17 台现场设备模型全部加载的时间，也不是客户 MySQL/PLC 的性能承诺**。

| 项目 | 优化前 | 优化后 |
|---|---:|---:|
| 根目录启动前的界面准备，源码未变化、含 Node 进程启动 | 5,359 ms 重新构建 | 1,205 / 860 / 795 ms 校验复用 |
| 单独的热缓存校验（不含 Node 进程创建） | 每次都构建 | 646 / 656 / 658 ms |
| 首次设置读取人为延迟 2.5 秒的受控场景，到真实登录入口 | 10,209 ms | 7,886 ms |
| 正常无延迟场景，到登录入口（不含启动前 Vite） | 8.49 / 7.73 秒 | 多次约 7.75–8.61 秒，**没有明显的大幅提速，不冒称 Unity 渲染变快** |

新隔离账户在复用源码依赖后，单独启动至登录约 9.24 秒。不能用之前首次依赖解压/系统冷缓存的长时间直接减它来宣称同倍数的整机提速。

首次构建仍需等待；刚构建后的第一次校验曾出现 5.28 秒，保留在原记录中，不保证任意冷磁盘/OneDrive 状态都小于一秒。分发安装包构建仍使用干净暂存目录，不把本地开发缓存混入发布。
