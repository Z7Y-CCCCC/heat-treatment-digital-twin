# 界面端口自动恢复与草稿保护

## 当前启动策略（2026-11-16，按 Ethan 新要求更新）

安装版与工作区共用 `desktop/displayGateway.cjs`：优先绑定上次保存的界面端口；若得到 `EADDRINUSE`（占用）或 `EACCES`（系统保留/拒绝监听），直接使用 `listen(0, '127.0.0.1')` 绑定并持有系统分配的空闲端口，再保存新端口。不是探测后释放，也不连接、结束占用者或删除 Windows 保留规则。新端口以后仍优先复用，失效时再次自动恢复。

### 草稿保护与中断恢复

1. 备份原 `ui-gateway.json`，原子保存新端口及 `pendingOriginMigration: { fromPort, toPort }`。迁移期间新地址的业务 HTTP/WS 均禁止使用，避免打开空白草稿后覆盖原内容。
2. 在业务界面、健康检查和 Unity 启动前，通过已内置的原生后台宿主迁移 WebView2，再用当前 Electron 会话迁移 Electron localStorage。无需安装 .NET SDK 或现场编译。两端均使用被本地拦截的离线页面，不向旧端口发送 HTTP 请求，不要求旧端口可用。
3. 在用户配置目录的 `recovery` 下备份源 localStorage 与目标原内容；校验逐键一致、源内容未变后，才清除待迁移记录、开放业务界面。保留旧地址的数据，不导出 Cookie，不更改采集地址、数据库、模型或服务。
4. 若中途退出，下次启动继续同一迁移；若目标端口又失效，再换空闲端口，但始终从最初的源地址恢复。目标冲突、未知 IndexedDB、写入/回读失败时保留迁移记录、备份与原数据，并给出明确错误，不静默丢弃草稿或覆盖新内容。

安装资源包含迁移模块、共用脚本，以及原生宿主内嵌脚本。原生构建生成匹配 EXE/DLL 摘要的能力标记，构建指纹覆盖共用脚本；资源准备缺少匹配能力时停止，不能带着旧宿主交付。新增检查不替代固定模板/空业务数据门禁。

## 2026-11-16 实际恢复

启动错误 `listen EACCES: permission denied 127.0.0.1:64974` 来自大屏自身的界面网关，而非 Unity 握手或采集数据库。本机 `netsh interface ipv4 show excludedportrange protocol=tcp` 确认当时系统保留段为 **64910–65009**；64974 没有普通监听进程。不能通过杀占用进程解决，也不应擅自删除 Windows 端口保留规则。

Ethan 明确同意更换固定本机界面端口并保留草稿。已将用户目录中的 `ui-gateway.json` 从 64974 更新为 **18081**；18080 经真实监听检测已占用，未终止其进程。采集地址仍是原 `deployment.json` 的 `http://127.0.0.1:3001`，配置原始字节核验未变。

### 本地状态保护

- WebView2：旧地址下全部 **6 项 localStorage** 已复制至新地址，逐项读取比较通过；迁移后回读旧地址，确认原状态未变。
- Electron 回退界面：旧地址下 localStorage 为 0 项，无待迁移记录。未清除 Cookie、账户、缓存、现场库或模型；Cookie 本身不按端口划分，没有导出或改写它们。
- 两种界面运行环境分别使用自身原用户配置目录。迁移通过本地拦截的离线空页面完成，不要求旧保留端口能监听，不加载业务页面、不上传数据。
- 原端口配置、源 localStorage 与目标迁移前状态保存在该用户目录的 `recovery/ui-origin-2026-11-16T00-44-21-460Z`，不在源码仓库中。原地址的数据仍保留，不是“先清空再换端口”。
- 有不同内容的目标键、写入配额失败、回读不符或源 IndexedDB 时，工具拒绝继续并保留旧端口。不会静默覆盖较新的目标草稿，不会跳过未知 IndexedDB 数据。

使用实际前端目录和当前采集地址在 **127.0.0.1:18081** 启动网关，`/admin` 和转发的 `/api/health` 均返回 200；验证进程随后关闭。没有自动启动现场大屏、重启采集服务、修改系统网络规则或生成安装包。

- 网关与迁移逻辑测试：12/12。
- WebView2、Electron 真实离线迁移测试：各执行首次迁移和退出后再次迁移，Unicode 草稿、值校验、原状态不变及幂等性通过。
- 部署和连接健康相关测试：17/17。
- 固定出厂模板一致性门禁通过。

## 历史人工恢复入口

最初人工恢复时采用“端口失效不自动换地址”的策略，现已被上面的自动迁移策略替代。配置损坏仍明确报错并保留原文件，不能猜测源地址。

人工指定端口工具仍仅在用户明确确认、关闭大屏及其启动错误窗口后使用；有待完成的自动迁移时拒绝改写，防止绕过草稿保护：

```powershell
node tools/repair-ui-origin.cjs --apply --port PORT
```

该工具先验证新端口能监听，备份原配置，构建本地 Debug 迁移辅助程序，分别迁移并校验 WebView2/Electron 状态，然后原子更新固定界面端口，再检测界面与原采集服务连通。失败不抹除原状态；更新端口后的验证失败会恢复原端口配置。工具不自动关闭正在使用的大屏，不自动切换采集目标或数据库。

隔离回归：

```powershell
node --test desktop/scripts/display-gateway-test.cjs tools/ui-origin-migration/transfer.test.cjs
node tools/ui-origin-migration/self-test.cjs
```

测试数据和 Debug 编译产物只位于忽略的 `output` / `obj` 中，不提交浏览器配置、草稿原始备份、凭据、EXE 或安装包。
