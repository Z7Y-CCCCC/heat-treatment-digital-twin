# 设备近景自动避遮挡

进入设备实体近景、透视或部件检查时，Unity 根据当前相机和选中设备自动判断视线遮挡。地板、基坑壁、厂房和其他仍可见的模型都参与判断；被挡住的下半部也参与，不只看设备中心。

- 当前设备不被这套逻辑透明化；它自己的透视/拆解仍使用原有检查设置。
- 只淡化遮挡物，不把整个工厂或所有设备统一调透明。合并为一个网格的工业地面以该网格为单位淡化。
- 随镜头旋转或对象移动重新判断；无遮挡后恢复原材质和原透明度。退出近景、切换设备或重建场景也恢复。
- 使用真实网格三角形和已共享的 BVH，不依赖 Collider；不会仅因为视线经过基坑外包围盒就把空洞当实墙。
- CPU 不可读取的导入网格采用保守包围盒淡化；这个近似只用于透明展示，不能用于设备/部件选择。
- 遮挡物使用独立材质副本、关闭深度写入和遮挡物阴影；原始 GLB、共享 PBR 材质、采集动画的 MaterialPropertyBlock 不修改。
- 每 80 ms 检测、27 个设备空间采样点；0.12 秒淡化、0.18 秒释放保持，防止微小视角波动反复闪烁。相机静止时复用材质，退出后释放。

## 验证

```powershell
node tools/device-occlusion-native-test.cjs
```

在独立 Unity Play Mode 场景执行真实渲染与生产代码：墙、旁边/后面的物体、无碰撞体、相机处于墙内、切换目标、不可读网格、工业基坑空洞、只有下半部被挡、精确原材质/阴影恢复、属性块和材质回收。最后载入真实井式炉 CAD，走真实 Dashboard 的设备近景入口。

本轮 21 项通过；真实井式炉 84,464 三角面。地下近景的前后原生渲染有 404,808 像素明显变化，源设备材质不变。截图输出为 `05-cad-before.png`、`06-cad-visible.png`，报告位于最新 `output/device-occlusion-*/result.json`。不是桌面截图伪装成渲染，也不是仅用网页或方块替代 CAD 验收。

没有接现场 PLC、没有启动采集服务、没有长稳或安装包验证。客户端代码需更新后生效；隔离生成的播放器不覆盖用户正在使用的程序。
