# 自动排布整线误报排查 · 2026-11-16

## 已确认的问题

Ethan 报告同一设备线上的八台设备均被提示“自动转向后仍无法兼顾外形留缝与原机构行程”。实际排查区分了两个问题：

1. **阻塞归因错误。** 自动对齐料口后，同侧设备共享同一辆小车的最大靠轨间距。原代码把“参与共同上限”也判为阻塞，因此只要一台设备需要的间距过大，弹窗就列出整排八台。整线方案被原子拒绝不等于每台设备分别不可排布。
2. **旧读取逻辑把正确框选再次翻转。** Ethan 已确认这八台设备的料口均为正确框选。只读测量确认「2号备料台」的进料口区域位于模型负 X 外表面，区域表面法线为负 X；旧读取逻辑又叠加设备专属入口的 −180°，将实际读取方向变成 +X。自动排布依据被翻转的方向转动整机后，料口落在背端，才得到导轨至料口所需最小间距约 6.866 米、原机构允许的最大间距约 4.484 米的拒绝诊断。**这是旧实现造成的几何来源重复叠加，不是 Ethan 框选错误，也不是备料台比其他模型大。** 其余七台在该次旧逻辑对照中分别满足留缝及原行程约束。

这里的最大间距是从导轨基准到设备料口的可达距离，**不是机构行程长度**。没有修改行程、模型缩放、PLC 含义或进出料口角色来放行。

## 只读对照与边界

- 原参数：复现整线拒绝；修正诊断后只指向「2号备料台」。
- 内存排除这台：其余七台及原小车可生成完整无外形重叠的推荐方案。
- 内存仅取消这台入口的 180° 偏转：八台及原小车可生成完整方案，原 X/Y、线长和小车路径不变。
- 成功对照的靠轨间距为 2.48 场景单位；该线比例为 0.8 场景单位/米，即 3.1 米。

以上为**旧实现的内存排查历史**，仅用于定位因果，不保存为现场配置，也不自动应用七台的部分方案。Ethan 已确认框选正确；本轮修复读取合同，不再要求现场清零 yaw、重新框选或手工修正料口。不能擅自删除现场覆盖、换用出料口或修改旧动作包。

## 本轮：框选区域就是绝对实际料口

Ethan 已明确确认框选正确，要求“框选并保存就是实际料口”。因此普通料口页、自动排布和原生运行端必须使用同一几何来源，不能把模型默认/设备微调当成两个需要用户额外辨认并人工协调的实际口。

旧实现把设备 `offset/yawDegrees` 相对叠加到当前型号默认，连已经保存的框选区域也被再次位移/转向。现场旧覆盖没有保存当时默认方向快照，也没有足够的料口变更审计，**不能追溯 −180° 的产生时间、操作人员或改动顺序，更不能推断其他设备的同类数值都是历史纠正操作**。已证实的是：「2号备料台」区域法线 −X 被旧读取逻辑叠加 −180° 后变成 +X，与正确框选不一致。

当前源码读取合同（共享解析器与原生 `LoadingPortPolicy` 已同步并通过隔离候选验证；运行文件覆盖状态见下节）：

- **模型该口为 null：仍为 null。** 设备区域不能凭空创建一个型号不存在的进/出料口。
- **设备专属 `region` 存在：它就是绝对实际口。** 位置只从该区域下沿中点派生，方向只从其表面法线的水平归一化投影派生；忽略旧 `offset/yawDegrees`，也不随之后的型号区域修改而再次搬动。
- **否则型号 `region` 存在：型号区域就是实际口。** 同样从区域角点和法线精确派生，忽略设备旧 `offset/yawDegrees`；即使型号 scalar 位置/方向在校验容差内，也不让它们成为第二个几何来源。
- **双方都没有 `region`：保留旧单点兼容。** 仅此分支继续使用型号单点加设备 `offset/yawDegrees` 的相对校准合同。
- 保留严格数值及真实矩形/法线校验；非法区域明确拒绝，不回退为臆造料口。
- 读取不迁移、不清空、不改写现场存储；不反转既有 PLC 含义，不改原行程、模型缩放、设备姿态或已保存布局。自动排布继续遵守真实外形留缝和原机构能力。
- 未变化的进出料信号和小车机构不随几何保存提交，避免料口几何保存重写 PLC 点位采样或新增机构默认值。

上一轮“模型默认/设备微调”的复杂展示、黄色提示和“方向沿用模型”恢复按钮属于中间方案，**不再是当前处理方式**。本轮不要求 Ethan 为了适配旧实现重新保存 yaw 或重修正确框选。
