# 安装窗口初始化检查

v2.3.3 的已发布安装程序存在启动缺陷：`System::Call` 的 DLL 模块名不是 shell 参数，内层双引号会成为模块名的一部分，实际返回 `error`，触发“安装窗口初始化失败”。仅验证解包后的大屏程序、资源哈希和编译通过不能覆盖这个问题。

修复取消 DLL 模块名的内层引号，显式禁止调用后卸载（`?!u`），保留初始化失败退出和原生窗口功能。自动回归编译同一份生产界面，并把原错误调用恢复到独立无安装 fixture；修正版必须能打开设置页，错误版必须被同一门禁拦截。

## 最终 EXE 门禁

`tools/package-installer.cjs` 在 NSIS 生成完成后调用 `tools/installer-startup-smoke.cjs`：

- 运行原始 EXE，不修改二进制或执行入口。
- SHA-256 绑定输入和验收证据，打开后再次核对文件没有变化。
- 只检查第一张设置页真实存在且“下一步”可用，然后关闭。**不点击下一步，不安装、不更新采集服务、不启动大屏。**
- 子进程使用私有临时目录和 `/D` 路径；`RunAsInvoker` 仅用于无提权的界面测试，不改变生产包的管理员权限要求。这不是完整安装/卸载验收，也不声称覆盖 UAC。
- 初始化报错、程序崩溃、页面未就绪或不能正常取消均导致构建失败。只清理本次临时目录及测试自己启动的进程，不操作现场数据或用户进程。

从 v2.3.4 开始，Release 清单必须携带与安装 EXE 哈希相同的 `installerStartup` 成功证据；收集和下载门禁均检查。所有原有模板、空业务数据、独立 MySQL 首启/重启、迁移、采集和资源完整性门禁仍保留。

2026-11-17 本地已对 GitHub v2.3.3 原包复现初始化失败；仅重压界面的隔离修正版通过真实 EXE 设置页启动检查。旧 Release 和 tag 不覆盖，新正式修复使用 v2.3.4。
