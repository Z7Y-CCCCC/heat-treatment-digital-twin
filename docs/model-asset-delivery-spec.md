# 模型资产与现场交付规范

这份规范的目标是把数字孪生模型从“按现场改代码”改成“按规范导入、标注、绑定、验收、发布”。

## Agent 交付要求

适用于依据图片、CAD 或既有模型**新建、修改、导出设备资产**。默认交付一个可直接导入现有后台的**完整单模型资产 ZIP**。只提供 GLB、料口坐标表、截图或报告都不算完整交付。此规范只约束资产生成，不要求改大屏程序、数据库结构、现有工程、固定出厂模板或安装包。

| 模块 | 必须交付的内容 | 没有或无法确认时 |
| --- | --- | --- |
| 模型 | 最终 `model.glb`、稳定的型号 ID/节点名、单位与坐标说明。源 Blender/CAD 工程和必要参考单独交付，不塞入资产 ZIP。 | 缺尺度依据时说明采用的尺寸假设及待测项目；不得把照片估算标作现场实测尺寸。 |
| 动作 | 对实际存在、需要展示的机构交付可预览动作；编译动作的 `motion.glb` 与 `motion.json` 必须成对，并与本次 `model.glb` 哈希匹配。 | 确认固定或无动作则说明不适用；无法判断实际行程或联动关系，列为待确认，不造虚假动作或 PLC 绑定。 |
| 拆解布局 | 交付型号层 `metadata.inspection`，用稳定部件 ID、真实节点、模型空间拆解偏移；完成布局后写 `metadata.disassemblyLayout: { "version": 1, "configured": true }`。 | 不可拆、无可独立结构或参考不足时，明确说明原因；不能把零偏移占位当作已做的拆解。 |
| 进出料口 | 同次生成真实交接口的型号默认数据，写入 `manifest.json → model.metadata.loadingPorts`。依据和验收以本规范的[默认进出料口](#默认进出料口)为准。 | 没有、无需交接或无法判定的口用 `null`，分别注明“不适用”或“待确认”；有交接需求但缺依据的资产不能标为已完成交接验收。 |

修改既有资产时，以用户确认的修改范围为准。只需补料口时，用现有的“仅进出料口设置”补充包和模块更新流程，不重导覆盖用户已经修正过的模型、动作、布局和设备实例。

## 交付流程

1. 导入模型：工程师上传完整 GLB/GLTF，后台记录模型 ID、名称、默认缩放和元数据。
2. 解析预览：系统读取模型节点、网格、三角面、材质、贴图和包围盒尺寸。
3. 资产规范：设置设备类型、版本、坐标规范、节点命名规则、LOD 策略、面数和贴图预算。
4. 部位绑定：选择模型节点，把节点绑定到标准点位字段，并配置旋转、平移、显隐、变色等动作。
5. 验收检查：系统检查模型可加载、节点可解析、性能预算、绑定点位完整性。
6. 发布版本：发布时保存资产规范、绑定配置、验收结果和性能统计快照；后续可恢复到某个发布快照。

## 门动作统一端点

“参考图片 → 建模 → 生成动作”交付固定：**0 为完全关闭、1 为完全打开**。模型原始门姿态、动作包 `nodes` 基准和 `door` 零帧均为关闭；半行程是实际中间姿态，终帧门板／滑架让开已配置的进出料通道。不得以信号取反代替正确建模。

新生成包记录 `endpointConvention.door = { closed: 0, open: 1 }`。生成器使用 `shared/motionEndpointConvention.mjs`；旧 authoring rig 的反向端点必须显式声明并在导出时标准化，不根据设备名称猜测。交付前检查 0／0.5／1 截图、关联机构、关门阻挡和开门连续交接。PLC 条件独立配置，包的标准端点不等于所有现场电平都必须相同。

输送辊筒沿用稳定动作 ID `rollers`／`hot_rollers`，不为进料和出料复制两份动作。后台双向试播按料口方向核验辊筒上表面的运动方向；风机、行走轮等不能误标为输送辊筒。试播只运行模型，不向 PLC 写数据。

只验证导出时，可指定 `MOTION_PACKAGE_OUTPUT_DIR` 到独立测试目录运行生成器；动作 GLB、轨迹和临时清单都进入该目录，不覆盖仓库清单或现场资产。

现有风冷台旧包属于兼容数据，不由此规则自动迁移。不得重新生成现场资产、替换现用包或反转已有绑定来“统一”正在运行的系统；此类迁移须另行审核和回归。

## 模型节点命名

模型节点名称必须稳定，不能由建模软件随机生成一堆 Cube.001、Object_37 这种名字。

推荐格式：

```text
role_part_action
```

示例：

```text
fan_rear_rotate
fan_front_rotate
door_front_lift
door_middle_slide
valve_gas_01
valve_gas_01_indicator
agitator_oil_01_rotate
cart_body
```

命名原则：

- 同一类设备的同一部件尽量同名，方便跨现场复用绑定模板。
- 可运动部件必须独立节点，不能和设备主体合并成一个网格。
- 需要变色的灯、阀、状态块必须独立材质或独立节点。
- 不依赖中文节点名做运行时绑定，中文可以作为后台显示名，节点路径要稳定。

导出时用最终 glTF 坐标检查尺寸和朝向：**米、+Y 向上、约定 +Z 为型号参考正向**，实际料口可以在任一侧。建模软件坐标、工厂世界坐标和 Unity 场景坐标都不能原样当成 glTF 根局部坐标。门轴、辊筒轴、滑轨等按真实机构设置枢轴；在静态模型、动作 rig 和拆解配置中保持相同部件语义。不明确知道参考比例时，报告比例依据和误差，不在现场绑定中补偿错尺度。

## 拆解布局生成

- 新布局用 `inspection.version: 2` 和 `offset_space: "model"`。用 `parts[].id` 区分部件，用 `node_names`（唯一名称）或 `node_paths`（完整路径）命中真实节点；`explode_offset` 按模型坐标设置。可独立透视的外壳在 `inspection.shell` 指定相应节点。
- 不把同一网格或其父子节点分给两个独立拆解部件；不靠重复模型撑出假拆解。正向拆解、暂停、反向组装、透视和关键部件选中都要预览。标签和镜头不能遮挡关键件；回装后回到初始位置，不能改变门关闭端点或料口基准。
- 框选料口时以**装配状态**、关闭动作的基准模型为准，但测量的是固定开口平面和送料面，不是挡在前面的活动门板。不要拿已经拆开的偏移姿态去量默认料口。

## 可绑定动作

当前运行时支持这些动作：

| 动作 | 用途 | 示例点位 |
| --- | --- | --- |
| rotate_speed | 按转速连续旋转 | rear_fan_rpm |
| rotate_angle | 按开度或角度旋转到指定位置 | front_door_open_pct |
| translate | 按行程平移 | cart_position |
| visibility | 按布尔值显示或隐藏 | flame_visible |
| color | 按开关状态变色 | valve_01_open |

绑定字段必须落到标准实时帧里，例如：

```json
{
  "source_group": "analog",
  "source_key": "rear_fan_rpm",
  "action": "rotate_speed",
  "axis": "y"
}
```

上例只是标准字段格式，不是现场点表。生成资产时不填客户专属点位 ID、PLC 地址、触发电平或账号。用户如需把动作连到现场信号，在已有后台按实际点表单独绑定；无有效数据时不得用随机信号冒充真实联动。单独的动作试播不等于现场设备在动。

## 性能预算

大屏不是离线渲染，模型必须为实时展示服务。

| 项目 | 默认上限 | 说明 |
| --- | ---: | --- |
| 三角面 | 200000 | 单个复杂设备建议控制在这个量级内 |
| 节点数 | 800 | 节点过多会拖慢遍历、绑定和实例化 |
| 贴图尺寸 | 2048 | 大屏远景不需要 4K/8K 贴图 |
| LOD | LOD0 必须可用 | LOD1/LOD2 后续用于远景降级 |

同型号设备批量出现时，优先复用同一个 GLB 和同一套绑定元数据，运行时才能继续做缓存、克隆和实例化优化。

## 验收标准

模型进入现场交付前至少满足：

- 完整 ZIP 通过现有导入检查；在独立演示工程中导入，后台能加载真实模型、动作和拆解，重新打开后能看到随包带入的默认料口。不用现场数据库或现场设备做首次导入试验。
- 包围盒尺寸方向正确，Y-up、Z-forward 或在资产规范里明确说明。
- 三角面、节点数、贴图尺寸不超过项目预算。
- 关键可动部位是独立节点，并能在后台节点列表选中。
- 已配置的绑定节点路径可解析。
- 门等有关联机构的动作已核对 0／0.5／1 及关门阻挡、开门让出通道；拆解与回装也已复验。
- 已配置的模型默认料口已核对下沿送料高度、外法线、入口／出口语义、对接间隙与交接路径；能在隔离演示中仅对一台设备微调、保存重开及恢复默认，其他同型号设备的默认值不变。
- 如已进行现场绑定，相关字段必须和现场实际 PLC／数据网关标准帧一致；未接现场时只报告资产与模拟验收，不宣称现场联调完成。
- 发布前保存一份快照，后续现场改坏可以恢复。

随交付附简短验收记录：资产 ID/版本、参考来源、是否按尺寸标定、适用/不适用/待确认的模块、两个口各自的测量依据和对接结论、运行的检查及限制。正侧视、装配/拆解对照、门 0／0.5／1、料口箭头与承料面对照图单独保存在交付材料或本地忽略目录；不把过程截图、现场数据、临时构建或原始导出提交仓库。

## 禁止做法

- 为某一个炉型在前端代码里写专用节点处理逻辑。
- 用模型文件名、节点中文名或设备名称猜业务含义。
- 把风扇、门、阀、状态灯和设备壳体合并到同一个不可拆分网格。
- 为了“看起来精细”使用远超预算的贴图和面数。
- 现场临时改源码发布。

## 默认进出料口

### 从最终模型确定位置

1. **先判定物料怎么走。** 从图纸、照片或已核实的工艺资料区分进料、出料或同口双向。确认开口在最终模型对应哪一侧、物料由何处承托。不能按型号名、正面朝向、包围盒中心或进料口反向去猜出口。
2. **测量真实交接口。** 测量固定口框、辊道或料盘与对接侧相交的位置。基准是**承料面／送料下沿的中点**，`Y` 是料盘或辊筒上表面的送料高度，不是门板中心、底座高度，也不是动画滑架的位置。用最终导出的 glTF 根局部空间，包括节点层级变换，不能直接复制 Blender、CAD 对象的局部坐标；不烘焙设备摆放、实例缩放或朝向，也不再手工翻转 Unity 的轴。
3. **分别确定外向方向。** `direction` 是固定料口表面**从设备朝外**的水平单位向量 `[dx, 0, dz]`。进料口也向外（朝来料方），不是物料进炉时的运动向量。斜面有效时取实际外法线在 XZ 平面的投影并归一化。两个真实交接口分别测量；同一个实体开口双向共用时可以为两项复制同一个位置、外法线和区域，不为了区分进出料而反转法线。
4. **有可靠开口边界优先提供真实区域。** `region` 的四点按环向顺序排列：`0 → 1` 为较低的水平下沿，`1 → 2` 上行，`2 → 3` 为上沿，`3 → 0` 回到下沿。四点须落在同一真实近竖直平面并构成矩形；`surfaceNormal` 为该面的真实外法线。使用 `loadingPortFromRegion` 计算下沿中点及水平外法线。只确认了承料点与方向、无法可靠测出区域时，用单点，不伪造矩形。顶部／底部开口等超出现有水平对接几何能力的情况，应明确标为待确认或不适用。
5. **不造空口。** 确认无出口填 `outlet: null`，同理可仅出料或无交接口。看不清时标“待确认”，不得用原点、门中心或镜像位占坑，不交付成“已经对齐”。如用 `nodeName`，指向场景可达、唯一、稳定的口框或承料节点；没有独立节点可用空字符串，不能填不存在或重复的名称。

### 使用现有资产结构

以下数值是演示，不是任何型号的默认值。示例入口在 `+Z` 有真实区域，出口在 `−Z` 仅提供单点。使用示例所列 `nodeName` 前，节点必须实际存在。将这段对象合并到现有 `manifest.json` 的 `model.metadata`，不要用它覆盖动作、拆解或其它元数据。

```json
{
  "loadingPorts": {
    "version": 1,
    "inlet": {
      "position": [0, 0.85, 1.2],
      "direction": [0, 0, 1],
      "nodeName": "port_inlet_frame",
      "region": {
        "version": 1,
        "corners": [[-0.35, 0.85, 1.2], [0.35, 0.85, 1.2], [0.35, 1.45, 1.2], [-0.35, 1.45, 1.2]],
        "surfaceNormal": [0, 0, 1],
        "nodeName": "port_inlet_frame"
      }
    },
    "outlet": {
      "position": [0, 0.85, -1.2],
      "direction": [0, 0, -1],
      "nodeName": "port_outlet_frame"
    }
  }
}
```

字段契约在 [shared/loadingPorts.mjs](../shared/loadingPorts.mjs)。`position`、`direction` 必须是三个有限的数字，不用字符串或 `NaN`；`direction[1]` 必须等于 `0`，水平分量非零。提供 `region` 时，`position` 和 `direction` 必须与它派生出的几何一致，不能再把基准点挪到框中心。

### 用户在现有后台微调

- **修正整个型号**：在 **模型库 → 模型管理 → 选模型 → 进出料口** 查看导入默认值。区域型料口用“框选料口区域”重画真实开口；已有单点可在“高级微调”修正 XYZ／水平外向方向，也可重新框选。保存后的型号默认值供未单独校准的设备复用。
- **只修正一台设备**：在 **工厂建模 → 车间编排 → 三维效果 → 选设备 → 进出料口配置** 保存设备独有的料口区域；已有单点也可用兼容的偏移／方向微调。实际使用优先级为设备区域、型号区域，再是单点和单点实例偏移。用“使用模型料口”及保存可清除设备选区，回到型号默认。型号没有对应的口时，先在模型层设置，实例不能凭空创建。
- **区分测量误差与实体布局错位**：只因料口测量不准才修改料口；小车轨面、设备位置或朝向错位，在现有对接／布局预览里校正实体，不通过挪动料口或翻转方向假装对齐。进出料信号由现场在现有后台按点表配置。上述操作不改原 GLB，不要求改任何程序。

## 模型资产包中的进出料口设置

模型资产包可携带四类内容：模型文件、拆解布局、动作、进出料口设置。完整单模型包和模型合集自动携带模型已保存的 `metadata.loadingPorts`；还可单独导出“仅进出料口设置”补充包，在已有模型上明确选择“进出料口设置”更新。

可移植内容为版本、入口／出口的模型根局部坐标、水平外法线、关联节点名称，以及已绘制区域的四角和表面法线。坐标保留在模型空间，不烘焙设备在工厂中的位置、旋转、现场偏移、PLC 点位／地址或进出料信号绑定。新设备引用导入的模型后复用该设置；已有设备的专属校准文档不被资产导入改写。

只更新料口模块时，模型文件、动作、拆解布局及其它元数据保持原状，并生成可独立回退的资产版本。旧包没有 `loadingPorts` 时不推断默认进出口、不清空已有设置；不能将缺失内容当成料口补充包。显式选择模块后，`{version:1,inlet:null,outlet:null}` 才表示清空两个模型默认料口，且可通过历史版本恢复。几何格式、数值、区域基准和节点引用不合法时拒绝写入。

这些包由用户另行导入，不自动进入空白出厂资源，也不在启动时迁移或重写现有资产。

## 打包与只读检查

1. 使用现有单模型资产包格式：ZIP 根目录是 `manifest.json`、`model.glb`，若有编译动作，再成对加入 `motion.glb`、`motion.json`。清单 `format` 为 `digital-twin-model-asset`、`version` 为 `1`；`files` 逐项记录除清单外的真实文件名、字节数和 SHA-256。不增加旁路 `ports.json`、重复模型、Blender 源或说明文档。ZIP 中的默认料口以清单为准。
2. 在仓库根目录执行现有的只读校验，或在隔离工程后台先用“检查资产包”，核对四个模块及更新范围，再导入。下面的检查读取 ZIP，不连接现场数据库：

   ```powershell
   node -e "require('./backend/services/modelAssetBundle').inspectAsset(process.argv[1]).then(r=>console.log(JSON.stringify(r,null,2))).catch(e=>{console.error(e.message);process.exitCode=1})" -- "D:/交付/设备资产.zip"
   ```

3. 导入检查能发现 ZIP、哈希和字段的问题，**不等于几何验收**。复验装配/拆解、门端点、正反向交接、模型默认值继承、单台设备微调及恢复默认；相关测试建议：

   ```powershell
   node --test frontend/tests/loading-port-region.test.mjs frontend/tests/loading-port-alignment.test.mjs frontend/tests/motion-endpoints.test.mjs
   ```
