# 热处理数字孪生大屏 - 客户部署说明

## 安装与启动

1. 双击安装包并完成安装。
2. 从桌面或开始菜单打开“热处理数字孪生大屏”。
3. 安装程序以管理员权限注册 `HeatTreatmentCollector` Windows 自动服务，首次准备随包 MySQL，并导入开发时的工厂、设备、点位、场景和组件配置。MySQL、Node.js、浏览器宿主和 Unity 运行时均由安装包提供，无需另行安装。
4. 安装版会注册为当前 Windows 用户登录后自动启动。

采集服务在电脑开机后由 Windows 启动，不需要用户登录桌面；Unity 前端打开或关闭都不影响 PLC 采集。服务异常退出时由 Windows 自动恢复。随包 MySQL 仅监听本机，使用独立数据目录和生成的账号密码，由采集服务管理，服务停止时先完成后端安全退出再关闭数据库。它不替换电脑已有的 MySQL 服务。已有 `database-config.json` 继续使用原连接，不会自动覆盖、清空或切换现场数据库。

安装包包含开发过程中使用的模型、上传音频和工厂配置；备份目录及备份文件不随包分发。运行历史默认不打包。现场可在现有配置上继续添加内容，再次启动不会重新导入模板。

正式现场不要使用 MySQL `root` 账号。应创建仅限 `localhost`、仅拥有本项目数据库权限的专用账号，并在 MySQL `my.ini` 中设置 `bind-address=127.0.0.1`。数据库端口不得通过路由器端口映射、云安全组或 Windows 防火墙暴露到公网。

## 两部分部署：Unity 前端 + Windows 采集服务

默认两部分部署在同一台现场电脑，不要求另有远程服务器。S7、Modbus TCP、OPC UA 只读采集、ERP/MES 接口、数据库、历史与备份都在 Windows 服务侧。Unity 和后台网页通过本机 HTTP / WebSocket 访问，展示端不会重复采集或建立第二份数据库。

安装包自动完成服务注册；也可在安装目录以管理员身份运行 `安装采集服务.ps1`。服务名是 `HeatTreatmentCollector`，默认接口 `http://127.0.0.1:3001`。在 Windows“服务”中可查看状态、停止或启动；只有明确停止服务、卸载或关闭电脑才会停止采集。后台登录锁定不影响采集。服务使用低权限 LocalService 账户及专用服务 SID，不依赖交互用户账户。

服务配置在 `%PROGRAMDATA%\HeatTreatmentDigitalTwin\collector-service.json`，现场数据在 `%PROGRAMDATA%\HeatTreatmentDigitalTwin\collector\`，不会随登录用户变化。服务首次准备数据库可能需要数分钟。安装时会等待就绪；端口冲突会明确失败，不会悄悄切换服务端口。

前端自动读取上述服务地址。需要修改前端连接地址时，可双击安装目录 `部署与连接.cmd`，或右键托盘选择“部署与连接…”。保存后只重启展示程序，不停止服务。服务未运行时显示明确的失败原因，不回退启动第二套采集后端。开发调试脚本仍保留原先本机子进程方式，不能将调试方式等同于正式服务部署。

已有用户目录的现场数据不会被安装脚本自动挪动或覆盖。升级前导出整站备份，再从新服务后台恢复；也可以停用旧程序后，在服务数据目录为空时显式传入 `-ImportDataDirectory 旧用户数据目录`。NAS 备份须给服务账户权限并使用 UNC 路径，不能依赖用户登录后映射的盘符。

卸载会安全停止并移除服务，但保留机器级现场数据。真正的无人登录验收仍须在现场重启电脑、先不登录 Windows，由另一受控诊断通道核对服务/日志和 PLC 数据，再登录打开 Unity 确认连续性。

## 本轮长稳保护与部署选项

- PLC 连接、读取都有独立超时兜底；现有设备超时配置保持不变（默认 5 秒），不会擅自统一改成 2 秒。持续失败从配置的重连间隔开始指数退避，最长 120 秒；丢弃旧连接迟到的数据，失联保留坏质量标记，不伪造缺失采样。
- 指标明细 `metric_snapshots` 默认保留 90 天；每次最多删除 10000 条、每批 500 条。有积压时隔 5 分钟继续，无积压每 6 小时检查。报警及操作事件 `event_logs` 不自动删除；不会删工厂配置、场景或发布版本。状态可在 `/api/health` 的 `historyRetention` 查看。数据库切换/恢复前暂停清理，完成后恢复。
- `mysql-host.log` 也纳入 10 MB gzip 轮转；`mysql-server.log` 最多一个 10 MB 活动文件及一个 10 MB `.previous`，不再无限追加。服务宿主日志同样最多保留活动及上一卷各约 10 MB。短期测试工具输出不等同于生产日志，测试结束后由工程师管理证据目录。
- 采集服务运行时发出系统防休眠请求，Unity 展示壳运行时阻止自动熄屏；退出即释放，不永久改当前电脑的电源计划。不能阻止人为关机、拔线、断电或 Windows Update 重启。
- 安装目录 `现场部署选项.ps1` 默认只检查。管理员显式加 `-ApplyPowerPolicy` 才复制当前电源计划并禁用交流供电下自动睡眠、休眠、熄屏、硬盘休眠、PCIe 节能及 USB 选择性挂起；原计划导出并保留，可用 `-RestorePowerPolicy` 恢复。不会更改电池策略、更新策略或保存账户密码。

仍需现场选择和验证的事项：BIOS 通电自启、Windows 更新维护窗口、交互账户自动登录、展厅键盘锁定、显示器/显卡重连、整机展示看门狗、微信/钉钉通知地址和签名密钥。不要把这些当作已经完成。服务不会在 Session 0 启动可见 Unity；显示器自动恢复大屏需要交互桌面。当前整站 ZIP 有完整性校验和轮转，但不是加密备份；NAS 还需服务账户读写权限。

分离后的兼容边界：原 DLNA 功能采用桌面窗口捕获，不能让 Session 0 的采集服务直接捕获交互用户桌面。该投屏路径仍需另接桌面捕获代理，不属于本轮已验证功能；若现场依赖 DLNA 投屏，应先完成代理接入再替换旧版本。PLC 采集与本机 Unity 展示不依赖桌面捕获。

不默认每 6 小时强制 `GC.Collect`：应先检查模型/纹理所有权与释放、内存趋势，再做可测量的空闲维护。运行时创建且仍被引用的资源，不会因为调用 `UnloadUnusedAssets` 自动消失。HDMI/驱动恢复须真实硬件拔插与睡眠恢复验收，短时软件测试不能证明显存数周无泄漏。

## 断电恢复与备份

- SQLite 应急库使用 WAL 和全同步写入，启动时自动执行完整性检查；损坏时会隔离损坏文件并从最新有效备份恢复。
- MySQL 生产库使用一致性 `mysqldump`，生成 `.sql.gz`；SQLite 生成 `.db`。两种数据库都会在启动、每 6 小时和正常退出时备份，默认保留最近 10 份。
- MySQL 备份密码通过短生命周期客户端配置文件传递，不写入命令行和日志；恢复前自动创建回滚备份，恢复失败会自动回滚。
- `backend.log` 记录后端正常运行输出，`backend-error.log` 单独记录后端错误输出，`desktop-error.log` 记录桌面壳启动和子进程异常；三类日志都按时间戳保留。
- 单个活动日志默认达到 10 MB 自动切卷并 gzip；压缩日志默认保留 30 天、最多 60 个、总计不超过 250 MB，程序运行期间每 6 小时自动清理一次。
- 工程师做隔离诊断时可设置 `APP_USER_DATA_DIR` 指定应用数据目录；正常客户部署无需设置。
- 后台“数据库连接 → 本机自动备份”可立即备份、下载或恢复；恢复前会自动创建回滚备份。
- 本机自动备份与现场电脑存放在一起，只能防断电或数据库损坏，不能防电脑丢失、硬盘损坏或整机报废。
- 采集服务在 Windows 开机后自动启动，无需自动登录；Unity 展示程序在用户登录后打开。无人值守来电恢复还需现场开启 BIOS 的“来电自动开机”；只有要求显示器来电后自动出现大屏时才需要安排交互账户登录。

## 整站灾备与新电脑恢复

后台“数据库连接 → 整站灾备（防电脑丢失）”可导出一个 ZIP 灾备包，并可配置每 1～168 小时自动生成、同步到 U 盘或 NAS。灾备包包含：

- 一致性 MySQL 压缩 dump 或 SQLite 数据库，以及车间、产线、设备、PLC 点位、历史数据、性能设置和平台编排等全部现场数据。
- 现场自行上传的 GLB/GLTF 模型文件。内置模型随安装包提供，不重复写入灾备包。
- 点位语音播报所生成或上传的 WAV、MP3、OGG、M4A 文件。
- 文件清单、大小和 SHA-256，用于导入前完整性校验。

现场备份步骤：

1. 填写“外部备份目录”，例如 `E:\数字孪生备份` 或 `\\NAS\factory-backup`，设置自动间隔并保存。
2. 点击“导出整站备份”做首次校验；后台应显示“已同步外部目录”。
3. 定期抽查外部目录中的 ZIP，并在备用电脑做恢复演练。未配置外部目录时，本机自动备份不能防电脑丢失。

现场电脑丢失或更换后的恢复步骤：

1. 在新电脑安装同版本或更新版本的软件并启动一次。
2. 进入后台“数据库连接 → 整站灾备”，点击“从整站备份恢复”。
3. 选择外置介质中的 ZIP，等待校验与恢复完成。
4. 核对车间、设备、PLC 点位、上传模型和语音播报，再进行现场 PLC 连通验收。

导入前软件会创建当前数据库回滚备份；导入失败时会恢复原上传文件。旧电脑的绝对数据库路径不会覆盖新电脑的数据目录。

## 现场配置

- 大屏首页用于展示数字孪生场景。
- 后台入口：软件内访问 `/admin`，或点击大屏的后台入口。
- 首次交付前，由工程师设置后台密码（8–128 个字符，没有通用默认密码），再交给普通用户使用。
- “系统设置 → 后台安全”可调整无操作自动锁定时间，范围 1–480 分钟，默认 30 分钟，保存后重启仍保留。有效会话内反复进入后台无需重复输密码；单次最长 8 小时，重启软件后重新验证。
- 离开前请先保存，再点击后台顶部、桌面页签栏或“后台安全”页的“立即锁定”。所有已解锁的后台会话立即失效，大屏和数据采集继续运行；若提示服务器尚未确认锁定，恢复连接后重试并确认成功再离开。
- 后台页签、侧栏和弹窗带平滑过渡；在后台不同页签间切换，或临时返回大屏再回到后台，未保存的表单草稿会保持原样。
- 草稿保留仅覆盖软件当前解锁会话；手动/自动锁定、刷新页面或退出软件前，仍应点击对应的保存按钮写入数据库。
- 无独显电脑建议在“系统设置 → 大屏渲染性能”选择“低配兼容”。
- PLC 地址和点位需要由现场工程师按设备实际情况配置。系统只读取数据，不向 PLC 写值。

### PLC 协议配置

设备编辑页目前只提供三种已真实接入的主流协议：

| 协议 | 默认端口 | 点位地址示例 | 主要配置 |
| --- | ---: | --- | --- |
| 西门子 S7 | 102 | `DB1.DBW0`、`DB1.DBX6.0` | Rack、Slot |
| Modbus TCP | 502 | `HR40001`、`IR30001`、`C00001`、`HR40003.2` | Unit ID、0/1 地址基准、字节序、字序 |
| OPC UA | 4840 | `ns=2;s=Channel1.Device1.Tag1` | Endpoint 路径、安全模式/策略、用户名和密码 |

Modbus 的 `HR/IR/C/DI` 分别表示保持寄存器、输入寄存器、线圈和离散输入；32/64 位数值不正确时，应按设备手册核对字节序和字序。OPC UA 密码不会通过后台查询接口明文返回；启用安全模式后，正式现场应核对服务器证书，只有明确处于调试阶段时才开启“自动信任服务器证书”。

## 点位语音播报配置

1. 进入后台“设备与点位配置”，在目标点位行点击“语音播报”。
2. 新增规则并选择触发方式：任意变化、BOOL 上升沿、BOOL 下降沿、等于阈值、向上跨越阈值或向下跨越阈值。
3. 填写播报文字。可使用 `{设备}`、`{点位}`、`{值}`、`{单位}`，运行时会替换为实际内容。
4. 设置冷却时间、音量和语速；PLC 信号容易抖动时应适当加长冷却时间。
5. 选择播放方式：
   - “系统文字转语音”适合实时播报动态数值。
   - “固定音频文件”适合固定报警话术，可由软件生成 WAV，也可上传现有音频。
   - “自动”会在有音频文件时播放文件，否则使用系统文字转语音。
6. 先点击“测试播报”，确认声音、音量和话术，再保存点位配置。

软件生成 WAV 时使用 Windows 自带的本地语音引擎，不需要外网或第三方账号。生成后的 WAV 内容固定；若话术包含实时温度、压力等变化值，请保留系统文字转语音模式。现场生成和上传的语音文件位于 `%APPDATA%\heat-treatment-digital-twin-desktop\uploads\audio\`，会和点位规则一起进入整站灾备包。

## 交付前实测结果

2026-08-07 使用外部 Snap7 仿真器和独立临时数据库完成隔离测试：

- `WORD/BOOL/REAL` 三类点位以 250/500/1000ms 持续采集，最近一轮延迟 p50 143ms、p95 237ms，最大帧间隔 267ms。
- 强杀 PLC 后 0.111 秒发布坏质量、4.152 秒判离线；PLC 恢复后 1.027 秒出现首个好帧、1.368 秒恢复在线，随后连续读取 8/8 成功。
- 高频写入中强杀后端，重启后最后一次已确认写入仍存在，数据库 `quick_check=ok`。
- 人为损坏主数据库后已验证自动恢复、损坏文件隔离、备份下载、手工恢复和恢复前回滚备份。
- 已验证 MySQL `.sql.gz` 创建、校验、恢复、失败回滚，以及 MySQL/SQLite 两类整站 ZIP 对数据库和上传模型的恢复。
- 已验证整站 ZIP 向外置目录临时复制、SHA-256 校验和原子改名，复制中断的半成品不会被当作正式备份。
- 已验证安全响应头、严格 CORS、5 MB 普通 JSON 上限、路径穿越拒绝、上传目录不可枚举，以及误绑定 `0.0.0.0` 时非本机写请求仍被拒绝。
- PLC 换算公式使用受限数学解析器，只允许 `x`、数字、四则运算和括号，不执行 JavaScript。
- 已验证桌面后端异常退出后自动恢复，以及 Unity 父进程退出后后台宿主自动清理。
- 后台与旧 Web 三维大屏已按需加载；进入 Unity 内嵌后台时不再预加载旧 Web 三维场景，基础入口包约 100.55 KB。
- 离线授权使用 Ed25519 签名许可证。正式安装包强制校验许可证，并将公钥放在客户数据目录；许可证还绑定持久安装锚点并兼容硬件指纹，普通系统更新不会改变授权。许可证过期、签名不匹配或绑定实例不一致时，业务 API 和 WebSocket 都会拒绝连接，但授权状态、重新安装许可证和安全退出仍可用。
- 2026-08-08 已完成 Modbus TCP 本地服务器真实读取（WORD、REAL、BOOL、输入寄存器）、字节序/字序组合、OPC UA 连接/会话/批量读取/失败清理流程、旧数据库字段迁移、协议地址校验和 OPC UA 密码掩码测试；S7 仿真断联与重连回归继续通过。OPC UA 正式上线仍需使用客户现场真实服务器和证书再验收一次。

## 商业交付注意事项

- 当前安装包未进行商业代码签名，Windows 可能显示“未知发布者”。正式对外销售建议使用企业代码签名证书重新签名。
- 软件默认只监听本机回环地址，不应直接暴露到公网。
- 当前版本已通过仿真 PLC、MySQL/SQLite 灾备恢复、进程强杀和生产安全边界测试。
- 仿真测试不能替代客户现场 PLC 型号、网络、点表和断电来电流程验收，正式上线仍需按现场点表逐点确认。
- 随包 MySQL 同时提供 `mysqldump.exe` 和 `mysql.exe` 用于本机备份恢复。手动连接其他版本的外部 MySQL 时，应使用对应版本的客户端工具；非标准目录可通过 `MYSQLDUMP_PATH` 与 `MYSQL_CLIENT_PATH` 指定。
- PostgreSQL 和 SQL Server 仍需使用数据库服务器自身的备份体系；后台会明确显示“不支持”，不会伪装成已备份。
- 离线升级包必须先通过后台发布契约校验（签名 + SHA-256 + 版本顺序），再执行安装；禁止直接覆盖安装目录。升级前导出整站灾备，升级后运行“自动验收”，失败时恢复灾备并安装上一版签名包。
